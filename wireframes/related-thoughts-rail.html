这条线上的旧念头

我原来以为注意力像一块饼，切给这件事，就少给那件事。可真正让人疲惫的，可能不是分配，而是频繁切换：每切一次，都要重新把整块心思搬回来。上周写方案时，我一下午只做了三件事，却觉得比开一天会还累。也许问题不在“给了多少”，而在“有没有连续地给”。

如果注意力是被任务牵引的，那“专注”就不是一种意志力，而是一种环境设计。把手机放到另一个房间，把要用的资料摊开，把下一步写成一句话——这些动作都比“我要专注”更可靠。今晚试了半小时，确实比昨天少了很多次摸手机。

稀缺会俘获注意力：当某样东西显得不够时，心思会不由自主地围着它转。可被俘获的注意力，往往看不见别的可能。要跳出来，先得给那件“不够”的事留出确定的边界。

05

实现约束与取舍

右栏和 prompt 同源；另记的 B 也要有标题/正文；不改召回与对谈协议。

上下文：和 prompt 同源

右栏不只读 guidance.notes：还要把 listClosedDescendantBodies(pageId) 返回的另记页（B）一起列入。建议主进程输出统一的 contextThoughts（pageId / title / source / body / kind），渲染层和 prompt 共用同一份来源；否则 B 只在模型里、不在右栏。当前页 A 已在中间，不重复。

全文：contextThoughts 带完整 body；prompt 仍可按上下文预算压缩。guidance 现有 excerpt 上限 1200 字，只作兜底。

展开：并读，全文不截断

并读：每条独立切换，可同时展开多条；默认展开列表第一条（回到 A 时是另记的 B）；头部“全部收起 / 全部展开”作用于本栏。全文展开后由右栏统一滚动，不做二次截断。

响应式：先判断宽度

  • > 1024px：主栏 + 340px 右栏并排。
  • ≤ 1024px：右栏收窄到约 280px，仍与会话并排；标题列表和主按钮保持在原位。
  • 关闭时网格切到 1fr + 34px，用占位窄条收口；不浮层、不遮罩。
  • 打开 / 关闭只改列宽，不改对谈滚动位置，也不锁页面滚动。

可达性

  • 念头头是 button，带 aria-expanded + aria-controls；会话里的标题只展示，不可点。
  • 焦点环用 moss，不靠颜色单独表达状态。
  • 右栏是布局的一部分，不做 focus trap；关闭后焦点交给右边缘窄条，展开新正文不抢焦点。

确认后的规则

  1. 并读：多条可同时展开；默认展开第一条；保留“全部收起 / 全部展开”。
  2. 全文：展开显示完整正文，不截断；长文按 pageId 取全文并缓存。
  3. 不跳转：右栏只读，不提供“打开旧念头”入口。
  4. 标题保留：引导卡按现有位置继续列出标题；只展示，不跳转、不改变会话位置。
  5. 上下文透明：所有进入模型的念头（含另记的 B）都出现在右侧；当前 A 已在中间，不重复。
