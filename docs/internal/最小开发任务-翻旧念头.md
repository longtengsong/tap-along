# 最小开发任务 · 翻旧念头

**任务编号：** MINI-ARCHIVE-001

**状态：** 已实现（A1–A4 代码完成，待真机验收）

**估时：** 2–2.5 人日（单人，含单测与回归）

**新增依赖：** 无

---

## 1. 一句话目标

用户点“先想到这”收住一个念头后，还能在“旧念头”里重新找到它、读完它。

当前 `pages:list` 只返回 `reading` 状态的页；已收住的页从界面消失，数据还在 SQLite 里，但用户读不到。这是笔记产品最硬的一个生命周期缺口。

---

## 2. 本任务做什么、不做什么

### 2.1 做

- AppBar 增加“翻旧念头”入口，新念头页和伴读页都能进。
- 新增“旧念头”列表：题眼、出处、已收住；按最近更新时间倒序。
- 点击一条旧念头，进入**只读**的伴读页：
  - 复用现有 `PageCard`；
  - 复用现有 `TalkStream`；
  - 复用现有 `ClosedNote`；
  - 没有落笔、改一改、补一句、再记一个入口。
- 从旧念头返回列表；从列表返回进入前的页面。
- 重启后仍能读到。
- 空列表、加载中、读取失败都有明确状态。
- 列表只取最近 50 条；不做搜索、过滤、分页。

### 2.2 不做

- 不做“重新打开讨论”或继续追问。
- 不做恢复已收住念头的编辑。
- 不做单条删除、批量删除。
- 不做全文搜索、按出处筛选、时间分组。
- 不改合上逻辑、不改对谈、不改引导、不改检索。
- 不新增数据库列、不做迁移。

## 3. 当前行为与目标行为

### 3.1 当前行为

```text
记下一个念头
  → 聊
  → 先想到这
  → 页面从 state.pages 移除
  → pages:list 只查 reading
  → 用户再也读不到这个念头
```

### 3.2 目标行为

```text
AppBar：翻旧念头
  → 旧念头列表（已收住）
  → 点一条
  → 只读伴读页：念头卡 + 对谈 + 来源
  → 回到上一条
  → 列表
  → 返回进入前的页面
```

## 4. 最小技术方案

### 4.1 数据层

`PagesRepository` 增加：

```ts
listClosed(limit: number): PageSnapshot[]
```

SQL 与 `listRecentReading` 相同，只改条件：

```sql
WHERE page_status = 'closed'
ORDER BY updated_at DESC, id DESC
LIMIT ?
```

- 复用现有列，不新增字段。
- `limit` 由 IPC 校验，默认 50，最大 100。
- 已有 `findById` 能读取 closed 页，直接复用。

### 4.2 IPC / preload

新增：

```ts
PAGE_CHANNELS.listClosed = 'pages:list-closed';

interface PageListClosedPayload {
  limit?: number;
}
```

- `listClosedPages` 校验 limit，返回 `PageListResult`。
- preload / `TapAlongBridge` 增加 `listClosedPages`。
- `api/tap-along.ts` 增加 `listClosedPages`。
- 错误码复用 `INVALID_LIST_LIMIT` / `LIST_FAILED`，不新增错误类型。

### 4.3 渲染层状态

`ViewState` 扩展：

```ts
type ViewState = 'new' | 'companion' | 'archive';
```

`state` 增加：

```ts
archivePages: PageRecord[];
archiveLoading: boolean;
archiveError: AppErrorCode | null;
archiveReturnView: 'new' | 'companion';
archiveReturnIndex: number;
archiveDetailOpen: boolean;
```

最小行为：

- `openArchive()`：
  - 记住当前 `view` / `currentIndex`；
  - `view='archive'`；
  - 拉取 `listClosedPages(50)`；
  - 映射快照为 `PageRecord`。
- `openArchivedPage(pageId)`：
  - 从 `archivePages` 找页；
  - 暂存当前 `state.pages` / `currentIndex`？不需要：旧念头是只读，不进入当前页叠。
  - 用 `state.pages = [page]`、`currentIndex=0`、`view='companion'`、`archiveDetailOpen=true`；
  - 返回时恢复进入前的 `pages` / `currentIndex` / `view`。
- `closeArchive()`：
  - 恢复进入前的 `view` / `currentIndex`；
  - 清空列表状态。
- `goBack()`：
  - 如果 `archiveDetailOpen`，回到 `archive`；
  - 否则沿用现有逻辑。
- `canGoBack`：
  - `archiveDetailOpen` 时 true；
  - archive 列表页显示“返回”，回到进入前页面；
  - 原页叠逻辑不变。

> 实现时可以把“进入前的页面栈”暂存在一个 `archiveReturn` 对象里，避免改动现有 `state.pages` 的语义。核心是：**旧念头详情只读，不参与当前页叠。**

## 6. 验收清单

### 6.1 功能

1. 新念头页点“翻旧念头”，能看到已收住的念头。
2. 伴读页点“翻旧念头”，同样能进。
3. 点一条旧念头：
   - 显示题眼、出处、完整对谈；
   - 不显示落笔/改一改/补一句/再记一个；
   - 来源仍可打开。
4. 从旧念头返回：
   - 回到旧念头列表；
   - 列表滚动位置尽量保留。
5. 从列表返回：
   - 回到进入前的页面；
   - 原页叠、当前页、输入草稿不被清空。
6. 重启后：
   - 旧念头仍在；
   - 能重新打开。
7. 没有旧念头：
   - 显示空状态，不报错。
8. 读取失败：
   - 显示失败和重试；
   - 不影响当前页。
9. 归档详情打开时：
   - 不会自动触发伴读；
   - 不会增加教学轮次；
   - 不会修改 `updated_at`。

## 8. 风险与边界

| 风险                 | 影响             | 处理                                                  |
| -------------------- | ---------------- | ----------------------------------------------------- |
| 归档详情污染当前页叠 | 返回后当前页丢失 | 旧念头详情只读，暂存进入前页栈，返回时恢复            |
| 列表太大             | 卡顿             | 先取 50，最大 100；不做分页                           |
| 旧念头被误当成可聊页 | 出现落笔框       | 详情页 `status='closed'`，BottomBar 只显示 ClosedNote |
| 打开旧念头触发老师   | 无来由的请求     | `openArchivedPage` 不发 teacher 请求；只读            |
| 读取失败影响主流程   | 用户当前页被清   | 归档错误独立状态，当前页栈不动                        |
| 返回路径混乱         | 用户迷路         | 明确两层：详情 → 列表 → 进入前页面                    |
| 归档列表无日期       | 不好定位         | 首版只按最近排序；日期后续再加                        |
