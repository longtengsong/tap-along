# TapAlong 后续开发计划

**更新时间：** 2026-11-04

**范围：** 抛开发布/打包/签名/CI/文档/QA 之后，剩余的产品开发工作

**前置结论：** 当前核心 AI 闭环已经完整；下一步优先补“笔记生命周期”和“AI 质量/成本”，而不是继续加联网功能。

---

## 1. 当前基线

### 1.1 已完成

- 新页边 → 理解引导 → 接点卡片 / 不追问 → 点击提问。
- 编辑/补一句后，维护回应结束自动刷新引导。
- FTS5 trigram + 2 字中文 LIKE + 同出处/词项打分。
- 召回质量基线：20 个夹具场景，recall@5 = 90%。
- 显式提问 → 意图路由 → Tavily 检索 → 带来源回答。
- 来源持久化、受控外链、引用警告。
- 中英文资源、396 条测试、覆盖率 97.6% / 93.4% / 97.8%。

### 1.2 已知产品缺口

- **已合上的页无法重新打开**（最严重）。
- 引导卡片没有正文锚点句（已规划未实现）。
- 引导失败/无候选后没有手动重试入口。
- 长对谈没有上下文预算，历史会无限增长。
- 引导/路由/research 只有结构测试，没有行为级评测。
- 本地召回对换述/语义相近场景仍有 10% 漏召回。
- 没有单页删除/归档管理。
- 新页边草稿关闭即丢。
- 无障碍没有系统审计。

### 1.3 明确排除

本计划不包含：

- 打包、签名、公证、图标、Bundle ID。
- README、隐私政策、CHANGELOG、CI、发布 QA。
- 数据导出/备份（属于发布数据安全）。
- 首次启动 onboarding / 演示模式（属于发布体验）。

这些另立发布计划。

## 3. 阶段 1：笔记生命周期闭环（2–2.5 人日）

### N1 翻旧念头 / 已收住念头入口

独立规划：`最小开发任务-翻旧念头.md`（已完成）。

**问题**

`closePage` 后页面从 `state.pages` 移除；`pages:list` 只查 `page_status='reading'`。用户收住后就再也读不到这个念头。

**最小方案**

- 新增“翻旧念头”入口（AppBar）。
- 新增 `listClosedPages` IPC。
- 旧念头列表：按 `updated_at DESC`，展示题眼、出处。
- 点击进入只读页：复用 `PageCard` + `TalkStream` + `ClosedNote`。
- 返回列表，不进入“改批注/补一句”流程。
- 空列表给一句“还没有收住的念头”。
- 不做重新打开讨论、不做恢复已收住念头编辑。

**验收**

- 收住一个念头后，能在“翻旧念头”里找到；
- 能读完整对谈及来源；
- 重启后仍在；
- 当前念头栈/返回行为不混乱。

**估时：** 2 人日。

### N2 列表体验补齐

- 列表数量上限 / 分页（先取 50）。
- 列表项来源、收住状态。
- 空状态。
- 不搜索、不过滤。

**估时：** 0.5 人日。

## 4. 阶段 2：引导体验增强（2–2.5 人日）

### G1 引导卡片的锚点句

独立规划：`最小开发任务-引导锚点句.md`（已完成）。

- 本地从当前正文 + 旧页片段提取最长公共子串；
- ≥3 字，≤40 字；
- 无公共片段不硬造；
- 卡片显示“从‘…’这处问起”。

**估时：** 1 人日。

### G2 手动重新找接点

独立规划：`最小开发任务-重新找接点.md`（已完成）。

**问题**

- 首次引导 `failed` / `no_candidates` 时，用户只能继续写；
- 没有“再找找”入口；
- 旧 guidance 存在时 `GuidanceService.run` 会跳过。

**最小方案**

- 在引导面板/页边卡下方提供一个轻量“再找找”动作，只在：
  - `failed` / `no_candidates`；或
  - 用户手动触发时。
- 复用 `guidance:run` 的 refresh 模式，增加 `force` 选项：
  - 允许覆盖 `failed` / `no_candidates`；
  - 手动触发时显示 `needed` 卡片；`not_needed` 显示固定提示（与首次引导一致）；
  - 用户已有消息时允许 refresh，但消息数变化丢弃。
- 不自动重跑；只在用户点按时。

**验收**

- 失败后点“再找找”能重新判定；
- 不重复追加卡片；
- 用户落笔后结果丢弃；
- 首次引导与编辑刷新不受影响。

**估时：** 1–1.5 人日。

## 5. 阶段 3：AI 质量与成本（2.5–3 人日）

### Q1 长对谈上下文预算

独立规划：`最小开发任务-长对谈上下文预算.md`。

**问题**

`buildTeacherMessages` 会把整页 `messages` 全部放进模型请求；长对谈会无限增长，成本和延迟不可控。

**最小方案**

- 增加确定性上下文预算（字符数优先，后续可换 token）：
  - 系统提示、当前页正文、压缩后代正文永远保留；
  - 最近 N 轮对谈优先保留；
  - 更早的历史按预算截断；
  - 保留最新用户消息；
  - 截断时插入一条“更早对谈已省略”的边界说明。
- 预算常量集中定义，可测试。
- 不引入摘要模型。

**验收**

- 长对谈请求大小有上限；
- 最新问题、当前页、压缩上下文不丢；
- 现有 prompt 指纹测试按预期更新；
- 短对谈行为不变。

**估时：** 1 人日。

### Q2 引导 / 路由 / research 行为评测

**问题**

当前测试主要验证消息结构和 JSON 校验，没有验证真实模型行为。

**最小方案**

- 扩展现有 `tools/prompts`：
  - guidance 场景：需要深挖 / 不需要 / 候选无关 / 非法 anchor；
  - router：research / reflect / 模糊；
  - research：引用、证据不足、网页注入。
- 离线组成测试 + 可选的 live eval。
- 不把 live eval 放进默认 CI。
- 记录基线通过率，不追求 100%。

**验收**

- `npm run test:prompts` 覆盖新场景；
- 失败能定位到具体规则；
- 不影响默认单测。

**估时：** 1.5 人日。

## 6. 阶段 4：语义召回（3–4 人日，条件启动）

**前置条件**

- 阶段 3 的评测显示：换述/语义场景 recall@5 明显低于目标；
- 或真实用户反馈“明明有相关旧页但没召回”。

**方案**

- 新增 embedding provider（OpenAI-compatible `/embeddings` 或本地模型）：
  - 与聊天 provider 分开配置；
  - Key 加密；
  - 页面正文 embedding 缓存；
  - 内容变化时失效；
  - hybrid：FTS/短词 + embedding 余弦，合并排序。
- 不引入向量数据库；SQLite BLOB + JS 余弦即可。
- 保留 FTS 作为降级路径。

**验收**

- recall@5 相对 90% 基线有可测提升；
- 没有 embedding Key 时自动回退 FTS；
- 页面规模 1000 条内可接受。

**估时：** 3–4 人日。

**如果评测显示 90% 已够用，则本阶段暂缓。**

## 7. 阶段 5：笔记管理与轻体验（3–4 人日）

### X0 导出备份（发布 P0，已完成）

独立规划：`最小开发任务-导出备份.md`（已完成）。

### X0.1 数据库错误提示（发布 P0）

独立规划：`最小开发任务-数据库错误提示.md`。

### X1 单页删除 / 归档管理

- 页边维护菜单增加“删掉这页”；
- 二次确认；
- 删除页面及其 guidance/FTS；
- 不提供批量删除（清空全部已有）。

**估时：** 1 人日。

### X2 新念头草稿恢复

独立规划：`最小开发任务-草稿自动恢复.md`。

- 新页边正文/出处输入时写入本地草稿；
- 重启/切换页后恢复；
- 收进页边成功后清空草稿；
- 不上传、不加密（本地明文，和 DB 一致）。

**估时：** 1 人日。

### X3 无障碍基础审计

- 键盘完整走一遍：新建 → 保存 → 引导卡片 → 落笔 → 修改 → 先想到这 → 翻旧念头；
- 焦点管理、Esc、Tab 顺序；
- 对比度、动态消息 aria-live；
- 减少动效偏好。

**估时：** 1–1.5 人日。

### X4 题眼（可选）

- 当前题眼是正文首行截断；
- 若产品需要，做一次异步模型题眼提取，失败回退首行；
- 不做也行，首行截断已经可用。

**估时：** 1 人日。

## 8. 暂缓 backlog（联网问答）

用户尚未决定，暂不排期：

- 证据不足时展示来源。
- 检索过程可见（routing / searching / answering）。
- 手动“查资料”兜底。
- Bocha 等中文搜索适配器。
- 搜索缓存/重试。
- 内联引用可点击。
- 多 provider 搜索选择。

这些都在 `最小开发任务-*.md` 中有独立方案，需要时再启动。

## 9. 推荐迭代顺序

### Sprint 1（约 3.5 人日）

1. 翻旧念头 / 已收住念头入口（2d，已完成）。
2. 引导锚点句（1d）。
3. 回归与手工走查（0.5d）。

### Sprint 2（约 3 人日）

1. 手动重新找接点（1.5d）。
2. 长对谈上下文预算（1d）。
3. 回归（0.5d）。

### Sprint 3（约 3 人日）

1. 引导 / 路由 / research 行为评测（1.5d）。
2. 单页删除/归档（1d）。
3. 新页边草稿恢复（0.5d）。

### 之后

- 根据评测决定是否启动 embedding/hybrid。
- 无障碍、题眼、联网 backlog 按优先级插入。

## 10. 关键决策

1. **已合上页打开后是只读，还是允许继续讨论？**
   - 建议：首版只读。继续讨论会重新引入“已合上页状态/轮次”复杂度，先不做。

2. **手动重新找接点是否覆盖 `not_needed`？**
   - 建议：手动触发时显示 `not_needed` 固定提示；自动刷新仍只处理 `needed`。

3. **上下文预算按字符还是 token？**
   - 建议：先字符，简单可测；后续有 tokenizer 再升级。

4. **是否现在做 embedding？**
   - 建议：先做行为评测和真实使用观察；没有数据不上。

5. **单页删除是否要进首版？**
   - 建议：进。只有“清空全部”没有单页删除，长期使用会很难受。

## 11. 完成定义

每个任务完成需满足：

- 有独立验收路径；
- 有单测/结构测试；
- 不破坏现有 396 条测试；
- `tsc`、`oxlint`、`oxfmt` 通过；
- 主进程覆盖率不低于 90%；
- 不引入新运行时依赖（embedding 除外，需单独评审）；
- 文档/计划同步更新。
