## 1. 这一步要解决什么

D8 已经能：

- Prompt 带图片；
- Gateway 发 `image_url`；
- 能力 supported 才发送；
- unsupported/unknown 纯文本。

但用户还看不到：

- 当前 provider 是否支持图片；
- 能不能选择“不发送图片”；
- 如何手动重新检测；
- 图片可能离开本机的隐私说明；
- 编辑器里当前模型不支持图片的提示。

本步补齐这些，并做发布前回归。

## 2. 本步做 / 不做

### 2.1 做

- Shared provider 类型：
  - `ImageInputMode = 'auto' | 'off'`；
  - `ImageCapabilityStatus = 'supported' | 'unsupported' | 'unknown'`；
  - `ModelProviderView.imageInput` / `imageCapability`；
  - `SaveModelProviderPayload.imageInput?`；
  - `providers:probe-images` 通道与 bridge。
- Provider 持久化：
  - `StoredProvider.imageInput` 默认 `auto`；
  - `imageCapabilities` 缓存（provider/model/baseUrl → status/checkedAt）；
  - 保存 provider / 清 Key 时失效缓存。
- `ImageCapabilityService`：
  - 读取/写入 7 天持久缓存；
  - `imageInput:'off'` → 不探测、不发送；
  - `probeActive()` 手动重测，绕过缓存但写回；
  - 并发 in-flight 不变。
- IPC/preload：
  - `providers:probe-images`；
  - `probeProviderImages()`。
- SettingsDialog：
  - provider 设置增加“图片输入：自动检测 / 不发送”；
  - 能力状态：支持 / 不支持 / 未检测；
  - “重新检测图片能力”按钮 + loading/error；
  - 常驻隐私说明。
- 编辑器提示：
  - 当前 provider `unsupported` 且当前 doc 含图 → 显示“当前模型不支持图片输入，图片不会发送给模型”；
  - 首次插图一次性隐私提示，localStorage key `tap-along:image-privacy-notice`；
  - `unknown` 不提示。
- 测试：
  - provider 配置/缓存/开关；
  - capability off/持久缓存/手动 probe；
  - IPC/UI；
  - 发布回归清单。

### 2.2 不做

- 不做强制发送 override。
- 不做按模型名静态能力表。
- 不做图片上传隐私弹窗阻断。
- 不做图片加密/本地脱敏。
- 不做导出导入。
- 不做新的模型供应商。
- 不做图片上下文预算/裁剪。

## 5. Provider 持久化

`src/main/services/providers.ts`：

```ts
interface StoredProvider {
  name: string;
  model: string;
  baseUrl: string;
  encryptedApiKey?: string;
  imageInput?: ImageInputMode;
}

interface StoredImageCapability {
  status: ImageCapabilityStatus;
  checkedAt: number;
}

export interface StoredProviderSettings {
  activeProvider: ModelProviderId;
  providers: Partial<Record<ModelProviderId, StoredProvider>>;
  imageCapabilities?: Record<string, StoredImageCapability>;
}
```

- `normalizeSettings`：
  - `imageInput` 缺省 `auto`，非法值回退 `auto`；
  - `imageCapabilities` 只保留合法 status/checkedAt。
- `buildState` 返回 `imageInput` / `imageCapability`（按 key 查缓存）。
- `save` 解析 `imageInput`；保存后失效该 provider 的图片能力缓存。
- `clearKey` 失效缓存。
- `ProviderRuntimeConfig` 增加 `imageInput: ImageInputMode`。
- `resolve` 返回 runtime config 带 imageInput。

### 5.1 缓存 key

```ts
const imageCapabilityKey = (
  providerId: string,
  model: string,
  baseUrl: string,
) => `${providerId}\u0000${model}\u0000${baseUrl}`;
```

- 同 provider 换 model/baseUrl 自然失效。
- 7 天 TTL；unknown 短 TTL（10 分钟）。

## 6. ImageCapabilityService 持久化

扩展构造参数：

```ts
interface ImageCapabilityCacheStore {
  read():
    | Record<string, { status: ImageCapabilityStatus; checkedAt: number }>
    | undefined;
  write(
    cache: Record<string, { status: ImageCapabilityStatus; checkedAt: number }>,
  ): void;
}

export class ImageCapabilityService implements ImageCapabilityResolver {
  constructor(
    configService: Pick<ProviderConfigService, 'resolveActive'>,
    dependencies: {
      fetchImpl?: FetchLike;
      now?: () => number;
      cache?: ImageCapabilityCacheStore;
      cacheTtlMs?: number;
      unknownCacheTtlMs?: number;
      timeoutMs?: number;
    } = {},
  ) {}
}
```

### 6.1 读取

- `resolveActive` 返回 config + `imageInput`：
  - `off` → `false`，不读缓存、不 fetch。
  - `auto` → 先读持久缓存 + 内存缓存，未过期直接用。
- 持久缓存 status/checkedAt；TTL 由 `now` 计算。

### 6.2 探测后写回

- 成功后写内存 + 持久缓存。
- 并发 in-flight 仍共用。
- `probeActive()`：
  - 忽略当前缓存，强制 probe；
  - 写回；
  - 返回 `status`；
  - `imageInput:'off'` 时直接 `unsupported`，不 fetch。

### 6.3 手动重测 IPC

`src/main/ipc/providers.ts`：

```ts
ipcMain.handle(PROVIDER_CHANNELS.probeImages, async (_event, id: unknown) => {
  if (!providerService.isProviderId(id)) {
    return { ok: false, errorCode: 'INVALID_PROVIDER' };
  }

  const result = await imageCapabilities.probeActive(id);
  return result.ok
    ? { ok: true, status: result.status }
    : { ok: false, errorCode: result.errorCode };
});
```

- 使用当前 provider 配置（key/model/baseUrl）。
- 探测只发内置小图，不发用户图片。
- 不写开发者记录。
- 失败返回受控错误；不抛未处理异常。

## 7. SettingsDialog

### 7.1 provider 表单

在现有 provider 设置后增加：

```text
图片输入
  ( ) 自动检测（推荐）
  ( ) 不发送
状态：支持 / 不支持 / 未检测
[重新检测图片能力]
```

- 保存 provider 时带 `imageInput`。
- `off` 时状态显示“不发送”，不探测。
- `auto` 未检测时状态“未检测”；首次带图请求会自动探测。
- 手动重测按钮：
  - loading 时禁用；
  - 成功更新本地 `provider.imageCapability`；
  - 失败显示 `ERROR_MESSAGE_KEYS`。
- 不提供“始终发送”。

### 7.2 常驻隐私说明

provider 图片输入区域下方：

```text
含图片的念头会在能力检测支持时，把图片发送给当前模型供应商。
```

- 中英文文案；不阻断保存。
- 设置页常驻，不只是一次性。

### 7.3 状态刷新

- 保存 provider / 切换 active / 手动 probe 后刷新 provider 列表。
- 连接测试不改变图片能力缓存（它不带图）。

## 8. 编辑器提示

### 8.1 不支持提示

`App.vue` 已有 provider 列表加载；把 active provider 的 `imageCapability` 传给：

- `NewPageScreen` → `NewPageForm` → `NoteEditor`；
- `CompanionScreen` → `PageCard` → `PageCardEditMode` → `NoteEditor`。

`NoteEditor` props：

```ts
imageCapability?: ImageCapabilityStatus;
```

- `imageCapability === 'unsupported'` 且 `countNoteImages(doc) > 0`：
  - 编辑器下方显示提示：
    “当前模型不支持图片输入，图片不会发送给模型。”
  - 不阻止保存；图片仍保存在本地。

- localStorage key：`tap-along:image-privacy-notice`。
- 第一次成功插入图片后显示一次性提示：
  “图片可能发送给当前模型供应商；可在设置里选择不发送。”
- 不阻断输入；关闭后写 key，不再显示。
- `NoteEditor` 发 `first-image` 事件；`NewPageForm`/`PageCardEditMode` 显示提示条。
- 设置页常驻说明仍保留。

## 12. 风险与边界

| 风险                     | 影响      | 处理                              |
| ------------------------ | --------- | --------------------------------- |
| 持久缓存与内存缓存不一致 | 状态错    | 单一读写入口；写后更新内存        |
| 设置页状态过期           | 误判      | 7 天 TTL + 手动重测               |
| off 仍探测               | 隐私/浪费 | resolve 前先读 imageInput         |
| 首次提示重复             | 打扰      | localStorage key + 只在成功插图后 |
| unsupported 提示误伤     | 用户困惑  | 只在含图时显示；unknown 不提示    |
| provider 旧数据          | 启动失败  | normalize 默认 auto/unknown       |
| 现有 provider 测试       | 回归      | 新字段默认值；fixture 补字段      |
| 手动 probe 并发          | 多次请求  | 复用 in-flight/缓存               |
| Electron store 写入失败  | 状态丢失  | 内存兜底 + 下次重测               |
