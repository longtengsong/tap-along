## 1. 计划目标

按已确认的技术方案，交付以下完整链路：

```text
新建念头
  → 写一句文字
  → 在任意光标位置粘贴图片
  → 图片压缩为 WebP、存文件
  → 保存
  → 读态卡片显示两行摘要 + “含图 N 张”
  → 点“查看全文”看只读图文浮层
  → 重启应用仍在
  → 带图提问时按供应商能力决定是否把图片发给模型
```

最终验收以技术方案 §16 为准。

## 2. 范围与前提

### 2.1 本期范围

- 新念头 + 编辑念头的正文富文本编辑。
- 图片行内插入、删除、预览、撤销/重做。
- 图片压缩（WebP，最长边 2400，质量 0.9）。
- 图片文件存储、引用表、清理。
- 读态两行摘要 + “查看全文”浮层。
- 草稿恢复、编辑取消、补一句。
- 导出目录（`backup.json` + `images/`）。
- 图片作为多模态上下文发送。
- 供应商图片能力检测 + 不支持时纯文本降级。
- 隐私提示（设置页常驻 + 编辑器首次插图一次性）。
- 旧数据库/旧草稿/旧页面兼容。

### 2.2 明确不做

- GIF 支持（输入阶段拒绝）。
- HEIC / TIFF / SVG。
- 图片裁剪、旋转、标注、对齐、拖拽改大小。
- 全文浮层复制/下载图片。
- “补一句”输入框和对谈输入框的图片。
- 归档列表缩略图。
- 相关旧念头/压缩上下文/网页来源/标题生成的图片。
- 强制发送图片的 override。

### 2.3 前提与依赖

- 开发机可安装 TipTap/ProseMirror 相关包，并能锁定版本。
- 现有 `npm test`、`npm run test:ui`、`npm run typecheck`、`npm run lint` 基线通过。
- 测试图片素材就绪：PNG、JPEG、WebP、BMP、AVIF、透明 PNG、竖图、大图、GIF/无效格式。
- 需要本地假供应商（HTTP）用于多模态/能力检测测试。
- 迁移前备份真实用户数据库（开发机）。
- 单人全职估算；如兼职或多人，按 §10 调整。

## 8. 数据迁移与发布

### 8.1 迁移前

1. 复制开发机 `tap-along.db` 到备份目录。
2. 用旧版本导出一份备份。
3. 记录当前 provider 配置（不导出 API Key）。

### 8.2 迁移验证

- 旧页面：两行摘要正常；首次编辑生成文档。
- 旧草稿：`{ body, source }` 自动转换。
- 旧 provider 设置：`imageInput` 默认 `auto`。
- 迁移后保存新页面、编辑旧页面、导出备份都正常。

### 8.3 发布前

- 技术方案 §16 全部勾选。
- 隐私提示文案就位（设置页 + 首次插图）。
- README / 首用页 / 设置页中“数据只在本机”类表述已补“图片会随模型请求发送”。
- 供应商能力检测默认 auto；DeepSeek 等文本模型应显示“不支持图片”。
- 导出目录在 macOS / Windows 都能创建、复制。

### 8.4 回滚说明

- 数据库迁移只加列/表，不回滚数据。
- 旧版本可读 `body`，但看不到图片；不要用旧版本编辑含图念头，否则 `body_doc` 会变旧。
- 回滚前先导出备份。

- **兼职（每天 4 小时）**：按核心 15.4 人日 × 2 ≈ 31 个半天，约 6–7 周；建议把 M1 和 M4 拉长。
- **多人协作**：每人独立分支/小 PR；D1 的 `note-doc.ts`、D8 的 `ChatMessage.imageIds`、D9 的 provider 类型是共享接口，先合并再并行。

```text
1. feat(shared): add NoteDoc model and plain-text projection

3. feat(images): add file store, tap-image protocol and image IPC

6. feat(card): show image count and read-only full-text overlay
7. feat(store): persist doc in draft/save/edit/append flows

9. feat(ai): send note images as multimodal context
10. feat(ai): detect provider image capability and fall back to text
11. test(e2e): cover paste/save/reopen/export flows
12. docs: update privacy and image behavior notes
```

每条提交保持可测试、可回退；D1/D2/D3 先合并，再开始 D4 的可视化工作。
