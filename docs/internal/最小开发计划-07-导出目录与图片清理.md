## 1. 这一步要解决什么

现在图片已经能保存、显示，但：

- 导出仍是单个 JSON 文件，图片带不走；
- 清空全部数据只删 DB，`userData/images/` 会残留；
- 取消编辑/崩溃/上传中会产生无引用图片、孤儿文件和临时文件，没有回收；
- `page_images` 行和磁盘文件可能长期不一致。

本步建立三条闭环：

```text
导出：目录选择 → backup.json + images/（不 base64）
清空：DB 清空 → images/ 清空
清理：无引用 30 天 / 孤儿 7 天 / 临时 1 天
```

```ts
export const BACKUP_FORMAT = 'tap-along-backup';
export const BACKUP_VERSION = 2;

export interface BackupImageMeta {
  id: string;
  fileName: string;
  mime: 'image/webp';
  byteLength: number;
  createdAt: number;
}

export interface BackupPayload {
  format: typeof BACKUP_FORMAT;
  version: typeof BACKUP_VERSION;
  exportedAt: string;
  pages: PageSnapshot[];
  images: BackupImageMeta[];
}

export interface ExportBackupResult {
  ok: boolean;
  canceled?: boolean;
  pageCount?: number;
  imageCount?: number;
  missingImages?: number;
  folder?: string;
  errorCode?: AppErrorCode;
}

export const buildBackupPayload = (
  pages: PageSnapshot[],
  images: BackupImageMeta[],
  exportedAt = new Date().toISOString(),
): BackupPayload => ({
  format: BACKUP_FORMAT,
  version: BACKUP_VERSION,
  exportedAt,
  pages,
  images,
});
```

- `images` 只包含实际复制成功的图片。
- `pages[].doc` 里的 imageId 与新结构对应。
- 不把图片字节写进 JSON。
- 旧备份 v1（单 JSON）仍可被未来导入识别；本步不做导入。

## 5. 目录导出

`src/main/ipc/backup.ts` 改为：

```ts
export interface BackupExportDependencies {
  documentsPath: string;
  showOpenDialog: (options: OpenDialogOptions) => Promise<{
    canceled: boolean;
    filePaths: string[];
  }>;
  mkdir: (path: string, options: { recursive: true }) => Promise<unknown>;
  copyFile: (source: string, target: string) => Promise<void>;
  writeFile: (
    filePath: string,
    data: string,
    encoding: 'utf8',
  ) => Promise<void>;
  stat: (path: string) => Promise<unknown>;
  now?: () => Date;
}
```

### 5.1 选择目录

```ts
const selection = await showOpenDialog({
  title: '选择导出位置',
  properties: ['openDirectory', 'createDirectory'],
});
```

- 取消 → `{ ok:false, canceled:true }`。
- 选中的是**父目录**，应用创建子目录：

```text
<parent>/tap-along-backup-2026-11-08-1530/
  backup.json
  images/
```

- 子目录重名：`-1`、`-2`…（用 `stat` 判断存在）。
- 子目录名使用本地时间；`dateStamp` + `timeStamp`。

### 5.2 导出步骤

1. `pages = repository.listAll()`；
2. `pageIds = pages.map(p => p.id)`；
3. `images = imagesRepository.listForPages(pageIds)`（已按 id 去重）；
4. 创建子目录和 `images/`；
5. 逐张：
   - `source = imageStore.pathFor(image.fileName)`；
   - `copyFile(source, join(folder,'images',image.fileName))`；
   - 成功 → 加入 `exportedImages`；
   - 失败/缺失 → `missingImages++`，继续；
6. `payload = buildBackupPayload(pages, exportedImages, now)`；
7. `writeFile(folder/backup.json, JSON.stringify(payload,null,2)+'\n', 'utf8')`；
8. 返回：
   ```ts
   {
     ok: true,
     pageCount: pages.length,
     imageCount: exportedImages.length,
     missingImages,
     folder,
   }
   ```

- 单张缺失不导致整体失败。
- `copyFile` 流式复制，不把图片读进内存。
- 只复制 DB 给出的 `fileName`；`ImageStore.pathFor` 负责路径边界。

### 5.3 错误

- 目录创建/backup.json 写入失败 → `EXPORT_FAILED`。
- 单张复制失败 → warning + `missingImages`，仍 `ok: true`。
- 取消 → `canceled: true`，不是错误。

## 6. 清空全部数据

`clearAllPages` 改为 async：

```ts
export const clearAllPages = async (
  repository: Pick<PagesRepository, 'clearAll'>,
  imageStore?: Pick<ImageStore, 'clear'>,
): Promise<PageClearAllResult> => {
  try {
    const cleared = repository.clearAll();
    await imageStore?.clear();
    return { ok: true, cleared };
  } catch (error) {
    console.error('清空会话数据失败：', error);
    return { ok: false, errorCode: 'SAVE_FAILED' };
  }
};
```

- DB 清空后清 `userData/images/`。
- 图片清理失败只记日志？这里返回 `SAVE_FAILED` 更诚实：DB 已清，文件可能残留；下次清理兜底。
- `registerPageHandlers` 增加可选 `imageStore` 参数；`main.ts` 传入。
- 现有单测改为 `await`；store 已 `await tapAlongApi.clearAllPages()`。

## 7. 清理服务

新增 `src/main/services/image-cleanup.ts`：

```ts
export const UNREFERENCED_IMAGE_RETENTION_MS = 30 * 24 * 60 * 60 * 1000;
export const ORPHAN_FILE_RETENTION_MS = 7 * 24 * 60 * 60 * 1000;
export const TEMP_FILE_RETENTION_MS = 24 * 60 * 60 * 1000;

export class ImageCleanupService {
  constructor(
    images: Pick<
      PageImagesRepository,
      'pruneUnreferenced' | 'listAllFileNames'
    >,
    store: Pick<ImageStore, 'listFileNames' | 'remove'>,
    now: () => number = Date.now,
  ) {}

  run(): Promise<{ removedRows: number; removedFiles: number }>;
}
```

### 7.1 步骤

1. `nowMs = now()`；
2. `unreferenced = images.pruneUnreferenced(nowMs - 30d)`；
   - 删除无引用且超期的 `page_images` 行；
   - 返回文件名；
3. 逐个 `store.remove(fileName)`；失败只记日志；计数；
4. `dbFiles = new Set(images.listAllFileNames())`；
5. `files = await store.listFileNames()`（含 mtime）；
6. 对每个文件：
   - 不在 `dbFiles`：
     - 临时文件（`name.startsWith('.tmp-')` 或 `name.endsWith('.tmp')`）且 `mtime < now - 1d` → 删除；
     - 其它孤儿且 `mtime < now - 7d` → 删除；
   - 在 `dbFiles` → 保留（有引用或行存在；行存在但文件丢失不在这里处理）。
7. 返回 `{ removedRows, removedFiles }`。
8. 失败只打日志，不影响启动。

### 7.2 启动接线

`main.ts` 在窗口创建后：

```ts
const cleanup = new ImageCleanupService(imagesRepository, imageStore);
void cleanup.run().catch((error: unknown) => {
  console.error('清理图片失败：', error);
});
```

- 不阻塞 `createWindow`。
- 应用退出时不需要等待清理完成。

### 7.3 边界

- 有引用但文件丢失：保留 DB 行；编辑器显示破图；导出计 `missingImages`；清理不删行。
- 草稿图片 30 天后可能被清理；草稿文字仍在（已确认取舍）。
- 已保存念头图片永远不在“无引用”集合里，不会被 30 天清理。
- 清空全部后 `images/` 为空；清理下次仍可处理残留。
