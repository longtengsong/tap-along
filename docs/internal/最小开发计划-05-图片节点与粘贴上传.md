## 1. 这一步要解决什么

前四步已经有：

- `NoteDoc` 与 `body_doc`；
- `page_images` / `page_image_refs`；
- `ImageStore` / `tap-image` 协议 / `images:create`；
- TipTap 纯文字编辑器与 doc 持久化。

现在把图片作为真正的 inline 节点插进正文：

```text
粘贴图片
  → 插入 pending 节点（占位）
  → 压缩为 WebP（2400 / 0.9）
  → images:create 写文件 + 元数据
  → 节点 imageId 填上
  → 保存 doc → page_image_refs
  → 卡片/全文用 tap-image://img/<id> 读取
```

## 4. NoteImage 节点

新增 `src/renderer/note/note-image-node.ts`：

```ts
import { Node, mergeAttributes } from '@tiptap/core';
import { VueNodeViewRenderer } from '@tiptap/vue-3';
import NoteImageNodeView from './NoteImageNodeView.vue';

export const NoteImage = Node.create({
  name: 'noteImage',
  group: 'inline',
  inline: true,
  atom: true,
  selectable: true,
  draggable: false,

  addAttributes() {
    return {
      imageId: { default: '' },
      alt: { default: null },
      // 仅编辑器内使用；保存/草稿时被 clone/strip 掉
      pendingId: { default: null },
    };
  },

  parseHTML() {
    return [{ tag: 'img[data-image-id]' }];
  },

  renderHTML({ HTMLAttributes }) {
    const imageId =
      typeof HTMLAttributes.imageId === 'string' ? HTMLAttributes.imageId : '';
    return [
      'img',
      mergeAttributes(HTMLAttributes, {
        'data-image-id': imageId,
        ...(imageId ? { src: `tap-image://img/${imageId}` } : {}),
      }),
    ];
  },

  addNodeView() {
    return VueNodeViewRenderer(NoteImageNodeView);
  },
});
```

### 4.1 attrs

- `imageId`：已上传图片 id；pending 时为空。
- `alt`：可选；本步粘贴时用文件名/空。
- `pendingId`：**瞬态**，只用于上传回调定位节点。
  - `cloneNoteDoc` / `parseNoteDoc` 不保留它；
  - 保存前必须无 pending；
  - 草稿 `stripPendingImages` 会删除 imageId 为空的节点。

### 4.2 HTML

- 渲染：`<img data-image-id="<id>" src="tap-image://img/<id>" alt="...">`。
- 解析：只认 `img[data-image-id]`；不读取任意外部 URL。
- 复制到别处时保留 `data-image-id`；粘贴回来可复用同一 id（引用表多对多）。
- 从外部应用复制图片通常给 File，走上传。

## 6. 压缩

新增 `src/renderer/note/image-compress.ts`：

```ts
export const ACCEPTED_IMAGE_TYPES = new Set([
  'image/png',
  'image/jpeg',
  'image/webp',
]);

export const MAX_IMAGE_EDGE = 2400;
export const IMAGE_QUALITY = 0.9;

export class ImageCompressionError extends Error {
  readonly code: 'unsupported' | 'decode' | 'encode';

  constructor(code: 'unsupported' | 'decode' | 'encode') {
    super(code);
    this.name = 'ImageCompressionError';
    this.code = code;
  }
}

export const compressImageFile = async (file: File): Promise<Uint8Array> => {
  if (!ACCEPTED_IMAGE_TYPES.has(file.type) || file.type === 'image/gif') {
    throw new ImageCompressionError('unsupported');
  }

  const bitmap = await createImageBitmap(file, {
    imageOrientation: 'from-image',
  }).catch(() => {
    throw new ImageCompressionError('decode');
  });

  try {
    const scale = Math.min(
      1,
      MAX_IMAGE_EDGE / Math.max(bitmap.width, bitmap.height),
    );
    const width = Math.max(1, Math.round(bitmap.width * scale));
    const height = Math.max(1, Math.round(bitmap.height * scale));
    const canvas = document.createElement('canvas');
    canvas.width = width;
    canvas.height = height;

    const context = canvas.getContext('2d');
    if (!context) throw new ImageCompressionError('encode');

    context.drawImage(bitmap, 0, 0, width, height);

    const blob = await new Promise<Blob | null>((resolve) =>
      canvas.toBlob(resolve, 'image/webp', IMAGE_QUALITY),
    );

    if (!blob) throw new ImageCompressionError('encode');
    return new Uint8Array(await blob.arrayBuffer());
  } finally {
    bitmap.close();
  }
};
```

- GIF 不进入白名单；动态 WebP 只取第一帧。
- 不放大：小图保持原尺寸。
- 输出固定 WebP；主进程只收 WebP。
- 不在主进程做压缩。

## 7. 上传管理

新增 `src/renderer/note/image-upload.ts`：

```ts
export type UploadPageImage = (
  bytes: Uint8Array,
) => Promise<CreatePageImageResult>;

export class NoteImageUploader {
  constructor(
    editor: Editor,
    uploadImage: UploadPageImage,
    callbacks: {
      onUploadingChange: (count: number) => void;
      onError: (errorCode: AppErrorCode) => void;
    },
  );

  addFiles(files: File[]): void;
}
```

### 7.1 流程

1. 过滤 `file.type.startsWith('image/')`；空 → 忽略。
2. 每个文件：
   - `pendingId = crypto.randomUUID()`；
   - 在当前 selection 插入：
     ```ts
     editor
       .chain()
       .focus()
       .insertContent({
         type: 'noteImage',
         attrs: { imageId: '', pendingId },
       })
       .run();
     ```
   - pending 计数 +1，回调。
3. 异步：
   - `compressImageFile(file)`；
   - `uploadImage(bytes)`；
   - 成功：按 `pendingId` 找节点，`setNodeMarkup` 填 `imageId`、`pendingId: null`；
   - 失败/压缩失败：删除该 pending 节点，`onError(IMAGE_INVALID | IMAGE_SAVE_FAILED)`；
   - 最后 pending 计数 -1，回调。
4. 编辑器已销毁（`editor.isDestroyed`）→ 不再 dispatch；已上传成功的图片行留给清理服务。
5. 多个文件可并发；每个 pendingId 独立定位。

### 7.2 定位节点

```ts
const findPending = (editor: Editor, pendingId: string) => {
  let found: { pos: number; node: ProseMirrorNode } | null = null;
  editor.state.doc.descendants((node, pos) => {
    if (node.type.name === 'noteImage' && node.attrs.pendingId === pendingId) {
      found = { pos, node };
      return false;
    }
    return true;
  });
  return found;
};
```

- 成功：`tr.setNodeMarkup(pos, undefined, { ...node.attrs, imageId, pendingId: null })`。
- 失败：`tr.delete(pos, pos + node.nodeSize)`。
- 不改动其他节点。

### 7.3 保存前保护

`NoteDoc` 增加：

```ts
export const hasPendingNoteImages = (doc: NoteDoc): boolean =>
  doc.content.some((paragraph) =>
    paragraph.content?.some(
      (inline) => inline.type === 'noteImage' && !inline.attrs.imageId.trim(),
    ),
  );
```

- `submitNewPage` / `saveEditing` 保存前检查：
  - 有 pending → `errorCode = 'IMAGE_UPLOADING'`，不调用 IPC。
- 表单按钮在上传中禁用；store 检查是安全网。
- 草稿保存时 `stripPendingImages` 继续生效；退出不会把 pending 写进草稿。

### 8.2 粘贴

`useEditor` 的 `editorProps.handlePaste`：

```ts
handlePaste: (_view, event) => {
  const files = extractImageFiles(event.clipboardData);
  if (files.length === 0) return false;
  event.preventDefault();
  uploader?.addFiles(files);
  return true;
};
```

`extractImageFiles`：

- 先 `Array.from(clipboardData.files)` 过滤 `type.startsWith('image/')`；

- 去重（按 name/size/lastModified 或对象引用）。
- 有图片就拦截；本步不处理“图片+文字”混合粘贴（图片优先，文字可在下一步优化）。

## 14. 风险与边界

| 风险                                          | 影响                   | 处理                                         |
| --------------------------------------------- | ---------------------- | -------------------------------------------- |
| `createImageBitmap`/canvas 在 Electron 的行为 | 压缩失败               | E2E 真实运行；失败提示                       |
| 剪贴板 File 类型缺失                          | 误判非图片             | 同时看 `type` 与文件名后缀；GIF 明确拒绝     |
| pending 节点被保存                            | 主进程 parse 拒绝/丢图 | 按钮禁用 + store `hasPendingNoteImages` 拦截 |
| pendingId 进入 body_doc                       | 数据污染               | cloneNoteDoc/parseNoteDoc 不保留；E2E 检查   |
| 多图并发定位错                                | 图插入错位置           | 每图独立 pendingId + `setNodeMarkup`         |
| 上传失败/组件卸载                             | 孤儿文件               | 上传成功但卸载 → 清理服务兜底；D7            |
| 粘贴 HTML 里带图片                            | 外链/破图              | 只处理剪贴板 File；不读取任意 URL            |
| 大图内存                                      | 卡顿                   | 2400 边压缩；并发上传；不做无上限解码        |
| 旧页面 doc 无图片节点                         | 兼容                   | NoteImage 只新增节点，旧 doc 正常            |
| 现有测试                                      | 回归                   | 图片上传只在有 File 时触发；文本粘贴不变     |
