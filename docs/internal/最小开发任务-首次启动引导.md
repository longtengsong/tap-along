# 最小开发任务 · 首次启动引导与演示模式

**任务编号：** MINI-ONBOARDING-001

**状态：** 已实现（O1–O6 代码完成，待真机验收）

**估时：** 1.5 人日（单人，含单测与回归）

**新增依赖：** 无

**发布属性：** P0。没有它，用户不知道要配模型，会把 mock 伴读当成真实 AI。

---

## 1. 一句话目标

用户第一次打开应用时，要么配置模型，要么明确进入演示模式。

不能出现：

```text
没配 API Key
→ 直接进入新念头
→ 伴读用固定 mock 话术
→ 用户以为 AI 已经工作
```

目标：

```text
首次打开
  → 说明“需要模型服务 / 笔记会发给供应商”
  → [配置模型] 或 [先试试演示]
  → 配置成功：正常使用
  → 演示：明确显示“演示模式”，随时可去设置
```

---

## 2. 本任务做什么、不做什么

### 2.1 做

- 启动后读取 `providerApi.list()`，判断当前激活供应商是否已配置。
- 未配置且本机未完成过首用引导时，显示**首次启动页**。
- 首次启动页提供：
  - “配置模型”：打开现有设置里的模型服务区；
  - “先试试演示”：关闭引导，进入新念头，并保留“演示模式”标识；
  - 简短说明：笔记会发送到模型供应商；未配置时伴读只用固定演示话术。
- 配置成功后自动关闭首次启动页；不再显示演示标识。
- 演示模式用 `localStorage` 记住“已完成首用引导”；下次启动不再拦全屏，但仍显示“演示模式”标识。
- AppBar 增加“演示模式”小标识，点击直接打开设置。
- 设置关闭后重新检查供应商状态。
- 供应商列表读取失败：不拦截用户，不误报“未配置”，直接进入正常界面。

### 2.2 不做

- 不做新的模型配置表单；复用现有 `SettingsDialog` 的模型服务区。
- 不做多步 wizard、动画、视频、账号注册。
- 不做模型供应商推荐/价格比较。
- 不做首用引导的云端同步。
- 不做“必须配置才能使用”的硬阻断；演示模式是明确选择。
- 不做首次启动的搜索 Key 引导；搜索是可选能力。
- 不改 provider 服务、加密、IPC。
- 不新增数据库列。

## 3. 状态矩阵

| 激活供应商     | 首用引导已完成 | 显示                        |
| -------------- | -------------- | --------------------------- |
| 已配置         | 任意           | 正常界面，无演示标识        |
| 未配置         | 否             | **首次启动页**              |
| 未配置         | 是（选了演示） | 正常界面 + AppBar“演示模式” |
| 读取失败       | 任意           | 正常界面，不误报            |
| 配置后又被清除 | 是             | 正常界面 + 演示标识         |

“首用引导已完成”只表示用户做过选择，不代表模型已配置。

## 4. 最小技术方案

### 4.1 App 层状态

`src/App.vue` 增加：

```ts
const providerCheckDone = ref(false);
const hasConfiguredProvider = ref(false);
const firstRunDismissed = ref(false);
```

初始化：

```ts
onMounted(async () => {
  // 现有 developer mode 读取...
  await refreshProviderState();
});

const refreshProviderState = async () => {
  try {
    const result = await providerApi.list();
    const active = result.ok
      ? result.state?.providers.find((provider) => provider.active)
      : undefined;
    hasConfiguredProvider.value = active?.configured === true;
  } catch {
    // 读取失败不拦截用户，也不误判为未配置。
    hasConfiguredProvider.value = true;
  } finally {
    providerCheckDone.value = true;
  }
};
```

`localStorage` key：

```text
tap-along:onboarding-done = '1'
```

- 只存在 renderer 本地；不涉及数据库。
- 清空应用数据不自动清 localStorage；可接受。
- 如果以后要“重置引导”，设置里再加。

计算：

```ts
const showFirstRun =
  providerCheckDone.value &&
  !hasConfiguredProvider.value &&
  !firstRunDismissed.value;

const demoMode = providerCheckDone.value && !hasConfiguredProvider.value;
```

### 4.2 FirstRunScreen

新增 `src/components/onboarding/FirstRunScreen.vue`：

```text
┌──────────────────────────────────────────────┐
│              轻叩伴读                        │
│                                              │
│  先接上你的伴读                               │
│                                              │
│  记下的念头会发送到你选择的模型供应商，        │
│  用来生成叩问；不配置时只能用固定演示话术。    │
│                                              │
│  [配置模型]        [先试试演示]               │
│                                              │
│  模型 Key 只加密保存在本机。                  │
└──────────────────────────────────────────────┘
```

- 居中、单列、窄屏可用。
- 不显示 AppBar 的“翻旧念头/设置”入口；避免首用就跳走。
- `配置模型` → `emit('configure')`；
- `先试试演示` → `emit('demo')`；
- 不做表单，不收集 Key。
- 文案中英文同步。

### 4.3 配置模型

App.vue：

```ts
const openFirstRunSettings = () => {
  firstRunDismissed.value = true; // 用户已做出选择
  settingsOpen.value = true;
};

const closeSettings = async () => {
  settingsOpen.value = false;
  await refreshProviderState();

  if (hasConfiguredProvider.value) {
    localStorage.setItem('tap-along:onboarding-done', '1');
  }
};
```

- 打开设置前先记“已选择”，避免关闭设置后又被首用页拦住。
- 设置关闭后重新检查：
  - 配置成功 → 首用页消失；
  - 仍未配置 → 正常界面 + 演示标识。
- 如果用户没有保存就关闭设置，仍可继续用演示模式，不反复拦截。

### 4.4 演示模式标识

`AppBar` 增加：

```ts
demoMode?: boolean;
```

- `demoMode` 为 true 时，在右侧显示一个小按钮：

```text
演示模式
```

- 点击 `emit('settings')`，打开设置。
- 位置放在“翻旧念头”和“设置”之间，文字弱化。
- 新念头、伴读、旧念头列表都显示；旧念头只读页也显示，提醒当前不是真实模型。
- 不弹窗、不阻塞。
- 配置成功后自动消失。

### 4.5 首用页关闭规则

- 选“先试试演示”：
  - `localStorage` 写 `onboarding-done=1`；
  - `firstRunDismissed=true`；
  - 进入新念头。
- 选“配置模型”：
  - `localStorage` 写 `onboarding-done=1`；
  - 打开设置；
  - 配置成功 → 正常；
  - 未配置 → 演示模式。
- 下次启动：
  - 有 Key → 正常；
  - 无 Key + 已完成 → 正常 + 演示标识；
  - 无 Key + 未完成 → 首用页。

### 4.6 供应商读取失败

- `providerApi.list()` 抛错或 `ok=false`：
  - 不显示首用页；
  - 不显示演示标识；
  - 按现有逻辑启动到新念头/最近念头；
  - 用户真正提问时，现有错误处理仍会提示。
- 这样避免“服务暂时读取失败”被误判成“从未配置”。

## 6. 验收清单

### 6.1 功能

1. 全新环境、无 Key、首次启动：
   - 出现首用页；
   - 能读清“笔记会发给模型供应商”；
   - 有“配置模型”和“先试试演示”。
2. 选“配置模型”：
   - 打开设置；
   - 保存有效 Key 并关闭设置后，首用页消失；
   - 演示标识不出现。
3. 选“先试试演示”：
   - 进入新念头；
   - AppBar 显示“演示模式”；
   - 点演示标识能打开设置；
   - 伴读明确使用固定话术。
4. 关闭设置但未配置：
   - 不再次弹首用页；
   - 继续显示演示标识。
5. 已有 Key 的用户：
   - 不出现首用页；
   - 不出现演示标识。
6. 供应商读取失败：
   - 不出现首用页；
   - 不出现演示标识；
   - 不误报。
7. 重启：
   - 已配置 → 正常；
   - 未配置 + 已完成引导 → 正常 + 演示标识；
   - 未配置 + 未完成 → 首用页。
8. 旧念头只读页：
   - 也显示演示标识（如果当前未配置）。
9. 中英文：
   - 首用页、演示标识、设置入口文案同步。

## 8. 风险与边界

| 风险               | 影响                | 处理                                 |
| ------------------ | ------------------- | ------------------------------------ |
| 把读取失败当未配置 | 已有 Key 的用户被拦 | 读取失败不拦截、不显示演示           |
| 用户关闭设置未配置 | 反复弹首用页        | 打开设置即记“已完成”，不重复拦       |
| 演示模式被忽略     | 用户以为 AI 已工作  | AppBar 持续显示“演示模式”            |
| localStorage 被清  | 再次首用            | 可接受；不涉及数据                   |
| 配置后状态未刷新   | 首用页不消失        | 设置关闭后必须重查                   |
| 首用页被当成设置页 | 用户找不到 Key 输入 | 首用页只放两个动作，配置复用现有设置 |
| 只读旧念头显示演示 | 误导                | 当前确实未配置，显示是正确的         |
