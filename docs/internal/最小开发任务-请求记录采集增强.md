# 最小开发任务 · 请求记录采集增强（回复 / 耗时 / Prompt 版本）

**任务编号：** MINI-PROMPT-TELEMETRY-001

**状态：** 已实现（D1–D5 代码完成，待真机验收）

**估时：** 0.5–1 人日（单人，含单测与回归）

**新增依赖：** 无

**关联前情：** 「用数据库请求记录优化提示词」讨论；现有 `request_inspections` 只记录发出去的 messages，没有回复和效果信号。

---

## 1. 一句话目标

开发者模式下，每条模型请求记录除了「发了什么」，还能回答「模型回了什么、花了多久、用的是哪一版 Prompt」。

```text
当前：request_inspections = 出站 messages
目标：request_inspections = 出站 messages + reply + latency_ms + prompt 版本指纹 + temperature
```

本任务只补数据，不改任何 Prompt 行为，也不改用户可见界面。

---

## 2. 本任务做什么、不做什么

### 2.1 做

- `request_inspections` 增加可空列：`reply`、`latency_ms`、`prompt_version`、`prompt_hash`、`temperature`。
- 旧库启动时自动迁移（沿用 `pages` 表的 `PRAGMA table_info` 检测方式）。
- `TeacherRequestInspector` 增加 `recordCompleted`：正常完成时回写回复与耗时。
- `ModelGateway` 的 `complete()` 与 `stream()` 两条路径都回写；流式在正常读完后回写累积文本。
- 老师请求带上 `prompt_version`（`PROMPT_VERSION`）和 `prompt_hash`（当前生效 Prompt 目录的 sha256 前 16 位）。
- 记录实际使用的 `temperature`。
- 更新受影响单测：inspector、gateway、数据库迁移。

### 2.2 不做

- 不做 `outcome` 回写（下一条用户消息、重试、编辑、另起一页、合上）。
- 不做导出脚本、JSONL、失败聚类。
- 不做开发者面板的新字段展示（新列先只进库，`TeacherMessage` 现有展示不变）。
- 不改记录开关：仍然只在开发者模式开启时记录。
- 不改请求参数、Prompt 文案、上下文组装。
- 不记录标题生成请求（没有 `requestId`，不在本期范围）。
- 不做数据加密、脱敏、上传、云同步。

## 3. 当前行为与目标行为

### 3.1 当前行为

```text
model-gateway.complete()/stream()
  → 发请求前 inspector.recordSent(messages)
  → 模型返回
  → 回复只进入 companion_log
  → request_inspections 里没有 reply / 耗时 / 版本
```

### 3.2 目标行为

```text
model-gateway.stream()
  → recordSent(messages, promptVersion, promptHash, temperature)
  → 逐块 yield，同时本地累积 reply
  → 正常结束
  → recordCompleted(requestId, reply, latencyMs)
  → 开发者面板仍显示原内容；库里该行已可 join 出完整回合
```

---

## 4. 最小技术方案

### 4.1 数据模型

```sql
ALTER TABLE request_inspections ADD COLUMN reply TEXT;
ALTER TABLE request_inspections ADD COLUMN latency_ms INTEGER;
ALTER TABLE request_inspections ADD COLUMN prompt_version TEXT;
ALTER TABLE request_inspections ADD COLUMN prompt_hash TEXT;
ALTER TABLE request_inspections ADD COLUMN temperature REAL;
```

说明：

- 全部可空，旧行保持可读。
- `reply` 存全文，便于直接转评测样本；与 `companion_log` 有重复，但本表是开发者开关下的独立副本，便于整表导出。
- `prompt_hash` 解决「开发者改过 Prompt 但 `PROMPT_VERSION` 没变」时无法区分版本的问题；哈希只存指纹，不存 Prompt 原文。
- `created_at` 语义不变，仍是请求发出时间；`latency_ms` 单独表达耗时。

### 4.2 记录生命周期

| 时点          | 动作                                                    |
| ------------- | ------------------------------------------------------- |
| 发请求前      | `recordSent` 写入 messages、provider、model、版本、温度 |
| 正常完成      | `recordCompleted` 合并 reply 与 latency                 |
| 失败          | `recordFailed` 置 `status='failed'` 与 `errorCode`      |
| 未配置供应商  | `recordFallback` 保持现状                               |
| 用户取消/中断 | 不写 reply，该行保持 `sent`（不新增状态，避免扩散）     |

### 4.3 版本指纹

- `prompt_version`：`PROMPT_VERSION`（当前 `companion-v2.0.0`）。
- `prompt_hash`：`sha256(JSON.stringify(resolvedCatalog)).slice(0, 16)`，在 `model-teacher` 组装消息处计算，随请求传给 gateway。
- 只用于区分「这一版 Prompt 的实际内容」，不参与任何逻辑判断。

### 5.1 实现约束

- `recordCompleted` 只对存在的 `requestId` 生效；找不到就静默忽略（与 `recordFailed` 一致）。
- 流式累积只在 gateway 内部进行，不改变对调用方的 chunk 时序。
- `latency_ms` 从发出请求到读完最后一块；失败请求也记录耗时。
- 不在 renderer/preload 新增 IPC 字段，避免扩大改动面。
- 迁移必须可重复执行，不能依赖启动顺序。

## 6. 验收标准

- 开发者模式开启，提一个问题后查库：该行 `reply` 与界面显示一致，`latency_ms > 0`，`prompt_version='companion-v2.0.0'`，`prompt_hash` 非空。
- 非流式请求（引导、连接测试）记录 `temperature=0`；流式老师请求当前未在请求体发送温度，记录为空，待后续决策（见第 10 节）。
- 开发者模式关闭：不产生新行。
- 供应商失败：`status='failed'`、`error_code` 有值、`reply` 为空。
- 生成中被用户取消：不写 `reply`，不抛新错误。
- 用旧版本数据库文件启动：应用正常，旧行仍可读取，新列为空。
- `pnpm typecheck`、`pnpm test` 全绿；`pnpm test:prompts` 不受影响。
- 开发者面板现有请求记录展示无回归。

## 7. 风险与回滚

| 风险                                    | 处理                                               |
| --------------------------------------- | -------------------------------------------------- |
| 流式回复全文进库，体积变大              | 单条通常 < 2KB；记录上限从 100 调到 2000 后约几 MB |
| 回复含用户隐私内容                      | 仍只在开发者模式记录、只存本机；文档补充说明       |
| `recordCompleted` 在 finally 误写中断态 | 用「正常读完」标志位控制，单测覆盖取消路径         |
| 迁移在旧库上失败                        | 迁移只做 `ADD COLUMN`，失败时启动流程保持现有容错  |
| 回滚                                    | 旧代码按显式列查询，新增列不影响；无需回滚数据     |

### 10.2 执行中的发现

1. **流式请求没有 temperature。** 老师问答走 `stream()`，请求体只有 `model/messages/stream`，温度由供应商默认值决定；本期不做行为变更，因此该列对老师请求为空。这会影响 Prompt 对比的可复现性，建议下一期决定是否把流式温度显式固定。
2. **`pnpm lint` 仍失败，但与本任务无关。** `wireframes/related-thoughts-rail.html`、`国际化文档.md`、`最小开发任务-长对谈上下文预算.md`、`高保真原型.html` 四个既有文件未格式化；本次改动文件已通过 oxlint 与 oxfmt。
3. **真实库当前只有 1 条历史记录**，采集合入后需要在开发者模式下实际使用一段时间才能形成样本。
