## 1. 一句话目标

一条命令把本机 `tap-along.db` 里的「请求回合」导出成 JSONL，并自动标出违反现有回复规则的样本，供人工审核和转成评测 fixture。

```text
request_inspections（出站 messages + reply + 版本）
  + pages.companion_log（下一条用户消息 / 编辑 / 另起一页）
  → tools/prompts/export-turns.mjs（只读）
  → turns.jsonl + 终端汇总
```

本任务只读数据，不写库、不改应用行为。

---

## 2. 本任务做什么、不做什么

### 2.1 做

- 新增只读导出脚本，打开 SQLite 时使用 `readOnly: true`。
- 按 `request_id` join `request_inspections` 与 `pages.companion_log` 中的老师消息。
- 每条回合输出：请求信息、完整 messages、回复、耗时、Prompt 版本/指纹、下一条用户消息、推导出的 `outcome`、规则失败列表。
- 复用 `tools/prompts/evaluate-reply.mjs` 做确定性规则筛查；期望语言由该回合最新的用户消息推断。
- 终端汇总：总回合数、按状态、按失败规则、按 `outcome`、按语言。
- 参数：`--db`、`--out`、`--only-failures`、`--since`、`--limit`、`--help`。
- 单测覆盖纯函数、参数解析、临时库上的 join 与空库。

### 2.2 不做

- 不改应用代码、数据库 schema、IPC。
- 不把 `outcome` 回写数据库（导出时推导，先验证规则是否够用）。
- 不做脱敏、匿名化、聚类、LLM-as-a-Judge。
- 不自动修改 `teacher-cases.json`。
- 不上传、不同步、不写日志。

## 3. 数据来源与推导规则

### 3.1 数据来源

- `request_inspections`：`messages`、`reply`、`status`、`model`、`prompt_version`、`prompt_hash`、`latency_ms`、`temperature`。
- `pages.companion_log`：JSON 数组，元素含 `role`（`teacher` / `user` / `maintenance`）、`text`、`requestId`、`actionType`、`createdAt`。
- 关联键：老师消息的 `requestId` = `request_inspections.request_id`。

### 3.2 推导规则（全部标记为推断值）

| 字段             | 规则                                                            |
| ---------------- | --------------------------------------------------------------- |
| `next_user_text` | 同一页日志中，该老师消息之后的第一条 `user` 消息的 `text`       |
| `outcome`        | 见下表；无法判断时为 `unknown`                                  |
| `rule_failures`  | `evaluateTeacherReply(reply, { language })`；`reply` 为空时跳过 |
| `language`       | 该回合之前最近一条用户消息的语言（`detectLatestLanguage`）      |

`outcome` 取值：

- `continued`：有下一条用户消息。
- `edited`：之后先出现 `actionType='edited_note'` 的维护记录。
- `forked`：之后先出现 `actionType='forked'` 的维护记录。
- `closed`：之后没有用户消息，且页面 `page_status='closed'`。
- `abandoned`：以上都不满足，且距该回合超过 24 小时。
- `unknown`：其余情况。

所有推断字段在输出中带 `inferred: true`，避免被当成人工标注。

### 3.3 输出格式（JSONL，一行一条）

```json
{
  "requestId": "req-1",
  "pageId": 12,
  "status": "sent",
  "providerId": "deepseek",
  "model": "deepseek-chat",
  "promptVersion": "companion-v2.0.0",
  "promptHash": "520d759124d4b78d",
  "latencyMs": 842,
  "temperature": null,
  "createdAt": 1762000000000,
  "messages": [{ "role": "system", "content": "..." }],
  "reply": "你注意到什么？",
  "nextUserText": "我觉得是带宽。",
  "outcome": "continued",
  "inferred": true,
  "ruleFailures": []
}
```

## 4. 实现方案

### 4.1 文件

| 文件                             | 内容                                                |
| -------------------------------- | --------------------------------------------------- |
| `tools/prompts/export-turns.mjs` | CLI 入口：参数解析、打开库、查询、写文件、汇总      |
| `tools/prompts/turn-export.mjs`  | 纯函数：日志解析、`next_user_text` / `outcome` 推导 |
| `tests/prompt-export.test.mjs`   | 纯函数、参数、临时库 join、空库与损坏库             |

### 4.2 CLI

```bash
# 默认库路径（按平台解析），输出到 stdout
node tools/prompts/export-turns.mjs

# 指定库与输出文件，只看失败样本
node tools/prompts/export-turns.mjs --db /path/tap-along.db --out turns.jsonl --only-failures

# 只看最近 7 天，最多 200 条
node tools/prompts/export-turns.mjs --since 2026-10-30 --limit 200
```

默认库路径解析顺序（取第一个存在的）：

1. `--db` 显式传入。
2. macOS：`~/Library/Application Support/TapAlong/tap-along.db`，回退 `tap-along`。
3. Windows：`%APPDATA%/TapAlong/tap-along.db`。
4. Linux：`~/.config/TapAlong/tap-along.db`。

缺少库文件时输出可读错误并以退出码 `1` 退出；`--help` 退出码 `0`。

### 4.3 边界处理

- `status='fallback'` 或 `messages=[]`：不参与规则筛查，仍导出，`ruleFailures=[]`。
- `reply` 为空（旧记录、失败、取消）：标记 `incomplete: true`。
- `companion_log` 非法 JSON：跳过该页并计入汇总警告，不中断导出。
- 同一 `request_id` 可能出现多条老师消息（异常数据）：取第一条并计入警告。

## 5. 验收标准

- 对当前真实库执行：命令成功，输出行数等于 join 命中数（当前预期 1 条）。
- 只读验证：执行前后数据库文件内容与 mtime 不变。
- `--only-failures` 只输出 `ruleFailures` 非空的行。
- 空库：输出 0 行，汇总正常，退出码 `0`。
- 库文件不存在/损坏：可读错误，退出码 `1`。
- 单测覆盖：`next_user_text`、`outcome` 各分支、参数解析、join、空库、损坏 JSON。
- `pnpm typecheck`、`pnpm test`、`pnpm test:prompts` 不受影响。
- 新增文件通过 `oxfmt --check`。

## 6. 风险与隐私

| 风险                              | 处理                                                 |
| --------------------------------- | ---------------------------------------------------- |
| 导出文件含真实笔记与回复          | 默认只写本地；文档提示「共享前人工脱敏」；不自动上传 |
| `outcome` 是弱标签                | 输出 `inferred: true`；只用于筛样本，不作为结论      |
| 旧记录缺少回复                    | 标记 `incomplete`，不参与规则统计                    |
| 误把 `--only-failures` 当质量结论 | 汇总同时输出总数与失败率，避免只看分子               |

3. **`outcome` 补充规则**：`appended_note` 视为 `continued`，`end` 视为 `closed`；与第 3.2 节一致，未新增枚举值。
