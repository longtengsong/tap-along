# 最小开发任务 · 重新找接点

**任务编号：** MINI-GUIDE-RETRY-001

**状态：** 已实现（R1–R5 代码完成，待真机验收）

**估时：** 1.5 人日（单人，含单测与回归）

**新增依赖：** 无

---

## 1. 一句话目标

引导失败或没有候选时，用户现在只能继续写；本任务给一个轻量的“再找找”入口。

```text
这次没找到能接住的旧念头。
[再找找]
```

只在**用户还没开始对谈**时出现；点击后重新判定一次，成功就出卡片，仍然没有就保持提示。

---

## 2. 本任务做什么、不做什么

### 2.1 做

- 首次引导 `failed` / `no_candidates` 时，在念头卡下方显示轻量提示和“再找找”。
- 点击后：
  - 先把 guidance 置为 `pending`，显示“正在旧念头里找能接住的线……”；
  - 调用 `guidance:run(mode='retry')`；
  - 成功 → 新卡片或“这一轮先不硬接”；
  - 仍然失败/无候选 → 提示和按钮再次出现。
- 只允许在**页面还没有用户消息**时手动重试。
- 重试不新增模型能力；复用现有召回 + GuidancePlanner。
- 重试结果覆盖旧的 `failed` / `no_candidates` guidance。
- 旧 guidance、编辑刷新、归档详情不受影响。

### 2.2 不做

- 不做“每次失败自动重试”。
- 不做无上限重试；用户点一次跑一次。
- 不做用户已经开始对谈后的重试。
- 不做手动选择候选页。
- 不做新的模型调用或新的 prompt。
- 不做重试次数统计、退避、缓存。
- 不改 FTS / 召回 / 联网问答。

## 4. 最小技术方案

### 4.1 共享类型

`GuidanceRunPayload.mode` 扩展：

```ts
mode: 'refresh' | 'retry';
```

- `refresh` 保持编辑后自动刷新语义；
- `retry` 只用于首次引导失败/无候选后的手动重试。

### 4.2 GuidanceService

`GuidanceRunMode` 增加 `'retry'`。

`execute` 的页面守卫：

```ts
if (mode === 'initial' && (page.guidance || userMessages)) return;

if (mode === 'retry') {
  if (userMessages) return;
  if (
    page.guidance &&
    page.guidance.status !== 'failed' &&
    page.guidance.status !== 'no_candidates'
  ) {
    return;
  }
}

if (mode === 'refresh' && page.guidance) return;
```

重试结果处理：

- `needed` / `not_needed`：和首次一样移除开场问题；
- `failed` / `no_candidates`：保留开场问题，写回新状态；
- 规划/召回失败：写 `failed`，让“再找找”再次出现；
- 不进入 `refresh` 的“静默失败”路径。

`GuidanceService.refresh` 扩展为接受 `'retry'`，或者新增 `retry` 方法；对外仍只暴露一个 `guidance:run`。

### 4.3 IPC / preload / API

- `guidance:run` 校验 `mode` 为 `refresh` 或 `retry`。
- `GuidanceRunPayload` 类型更新。
- preload / `tapAlongApi.runGuidance` 不需要新方法，只传新 mode。
- 无效 mode 仍返回 `TEACHER_INVALID_REQUEST`。

### 4.4 渲染层

`CompanionScreen` 的 `showGuidance` 条件：

```ts
const canShowRetry =
  page.status === 'reading' &&
  !page.messages.some((item) => item.role === 'user') &&
  (guidance?.status === 'failed' || guidance?.status === 'no_candidates');

const showGuidance =
  ...existing... || canShowRetry;
```

`GuidancePanel` 增加分支：

```vue
<div
  v-else-if="
    guidance.status === 'failed' || guidance.status === 'no_candidates'
  "
  class="guidance guidance--retry"
  role="status"
>
  <p>{{ t('guidance.retryHint') }}</p>
  <button type="button" @click="emit('retry')">
    {{ t('guidance.retryAction') }}
  </button>
</div>
```

- `failed` 和 `no_candidates` 使用同一句提示；不区分内部错误。
- 按钮使用现有文字按钮样式，不抢主操作。
- `pending` 时按钮自然消失。

`CompanionScreen` 增加 `retry` emit，`App.vue` 接 `retryGuidance`。

`retryGuidance`：

```ts
const page = currentPage.value;
if (!page || page.messages.some((item) => item.role === 'user')) return;
const previous = page.guidance;
page.guidance = createPendingGuidance();
page.guidanceError = '';
const result = await tapAlongApi.runGuidance({
  pageId: page.id,
  mode: 'retry',
});
if (!result.ok) {
  page.guidance = previous;
  page.guidanceError = t('guidance.retryFailed');
}
```

- 成功由 `guidance:updated` 事件落盘；
- 失败时恢复旧状态，避免 pending 卡死；
- 用户已有消息时不显示入口，store 再做一次防御。

### 4.5 文案

```text
guidance.retryHint    这次没找到能接住的旧念头。
guidance.retryAction  再找找
guidance.retryFailed  这次没找成，稍后再试也行。
```

英文：

```text
No earlier thought could catch this one this time.
Look again
That attempt didn't work. You can try again later.
```

- 不使用“失败/错误”这类技术词；
- 不承诺“再找一定找得到”。

## 6. 验收清单

### 6.1 功能

1. 首次引导 `failed`：
   - 显示“这次没找到能接住的旧念头。”；
   - 点“再找找”进入 pending；
   - 成功出新卡片或“不硬接”。
2. 首次引导 `no_candidates`：
   - 同样显示重试入口；
   - 重试仍无候选时提示回来。
3. 首次引导 `needed` / `not_needed`：
   - 不显示重试入口；
   - 行为不变。
4. 用户已经开始对谈：
   - 不显示重试入口；
   - 手动调用也被 store 拒绝。
5. 重试请求本身失败：
   - 恢复旧 guidance；
   - 显示 `guidance.retryFailed`；
   - 不留下 pending。
6. 重试成功后：
   - 旧 `failed`/`no_candidates` 被覆盖；
   - 开场问题按 needed/not_needed 规则移除；
   - 点击卡片正常。
7. 编辑后刷新、翻旧念头：
   - 行为不变。

### 6.2 质量

- `npm test` 全绿；覆盖率 ≥ 90%。
- `tsc --noEmit`、`oxlint`、`oxfmt --check` 通过。
- 无新增依赖、无数据库迁移。

## 8. 风险与边界

| 风险                 | 影响           | 处理                                              |
| -------------------- | -------------- | ------------------------------------------------- |
| pending 卡死         | 用户看不到按钮 | API 失败恢复旧 guidance；事件失败写 failed        |
| 用户已开始对谈仍重试 | 卡片打断对话   | UI 隐藏 + store 防御 + service 守卫               |
| 覆盖正常 guidance    | 丢失卡片       | 只允许覆盖 failed/no_candidates                   |
| 无限重试成本         | 模型调用增加   | 用户手动触发，一次点击一次；不自动重试            |
| 重试仍失败           | 用户失望       | 文案不承诺成功；按钮回来                          |
| 与编辑刷新冲突       | 状态错乱       | retry 与 refresh 分开；页面已有用户消息时都不显示 |
