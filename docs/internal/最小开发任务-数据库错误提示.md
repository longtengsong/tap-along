# 最小开发任务 · 数据库启动错误提示

**任务编号：** MINI-DB-ERROR-001

**状态：** 已实现（B1–B4 代码完成，待真机验收）

**估时：** 0.5–1 人日（单人，含单测与回归）

**新增依赖：** 无

**发布属性：** P0。数据库打不开时，现在只写 console 然后应用直接退出，用户完全不知道发生了什么。

---

## 1. 一句话目标

启动时如果本地数据库打不开，不要静默退出：

```text
轻叩伴读
无法打开本地数据

数据目录：/Users/…/Library/Application Support/tap-along

[打开数据目录]  [退出]
```

用户至少能看到原因位置，能先备份/检查，再决定是否重试。

---

## 2. 本任务做什么、不做什么

### 2.1 做

- 把当前 `app.whenReady()` 里的启动逻辑抽成可失败的初始化流程。
- 数据库 `openDatabase` 失败时：
  - 记录完整错误到 console；
  - 用系统原生对话框显示可读说明；
  - 显示数据目录；
  - 提供“打开数据目录”；
  - 提供“退出”。
- 对话框语言跟随系统语言：中文 / 英文。
- 用户关闭对话框/退出后，应用正常退出，不留下半初始化状态。
- 打开数据目录失败不二次崩溃。
- 新增纯函数测试文案、路径与错误分类。

### 2.2 不做

- 不做自动修复数据库。
- 不做自动备份/恢复。
- 不做数据库迁移回滚。
- 不做崩溃上报/日志文件。
- 不做设置页里的“数据目录”入口（后续可选）。
- 不做重试按钮；数据库损坏时无脑重试没有意义。
- 不改数据库 schema、迁移、FTS。
- 不改正常启动路径。

### 3.1 当前行为

```text
app.whenReady()
  → openDatabase()
  → 抛错
  → console.error
  → app.quit()
  → 用户只看到应用闪退

### 3.2 目标行为

  → initializeApplication()
  → openDatabase() 抛错
  → 显示原生错误对话框
       message: 无法打开本地数据
       detail: 数据目录 + 简短说明
       buttons: 打开数据目录 / 退出
  → 用户选择
  → 退出应用
```

## 4. 最小技术方案

### 4.1 启动初始化抽离

`src/main.ts` 当前：

```ts
app.whenReady().then(() => {
  try {
    database = openDatabase(...);
    // 大量服务初始化 + 注册 IPC
    createWindow(...);
  } catch (error) {
    console.error(...);
    app.quit();
  }
});
```

改为：

```ts
const initializeApplication = async () => {
  try {
    database = openDatabase(allocateDatabasePath(app.getPath('userData')));
    // 原有初始化
    createWindow(...);
  } catch (error) {
    await showDatabaseStartupFailure({
      error,
      dataDirectory: app.getPath('userData'),
    });
    app.quit();
  }
};

app.whenReady().then(initializeApplication);
```

注意：

- `initializeApplication` 只处理启动阶段；不改变后续 IPC 注册。
- `database` 若部分初始化，退出前调用 `closeDatabase` 需要判空；当前 `before-quit` 已处理。
- 不在 catch 里再次 `createWindow`。

### 4.2 原生错误对话框

新增 `src/main/services/startup-error.ts`：

```ts
export interface StartupFailureOptions {
  error: unknown;
  dataDirectory: string;
  locale: string;
}

export const buildStartupFailureContent = ({
  error,
  dataDirectory,
  locale,
}: StartupFailureOptions): {
  title: string;
  message: string;
  detail: string;
  openButton: string;
  quitButton: string;
}
```

中文：

```text
无法打开本地数据
数据目录：{dataDirectory}

请先确认该目录存在且可写，或从备份恢复数据。
```

英文：

```text
Could not open your local data
Data folder: {dataDirectory}

Check that the folder exists and is writable, or restore it from a backup.
```

- `error` 只用于 console，不把原始错误直接展示给用户，避免泄露堆栈/路径细节过多。
- 可附加一行简短原因分类：
  - 权限问题：`无法读取或写入数据目录。`
  - 其他：`本地数据暂时打不开。`
- 分类用 `code`/message 判断，不做复杂映射。

### 4.3 打开目录

`src/main.ts`：

```ts
const result = await dialog.showMessageBox({
  type: 'error',
  title,
  message,
  detail,
  buttons: [openButton, quitButton],
  defaultId: 0,
  cancelId: 1,
  noLink: true,
});

if (result.response === 0) {
  await shell.openPath(dataDirectory);
}
```

- `openPath` 失败只 `console.error`，不再弹窗。
- 打开目录后再退出；用户可以先看文件。
- 如果用户选择“退出”，直接退出。
- 对话框是模态的（不传 window 或传当前 window，启动阶段没有窗口）。

### 4.4 语言

- 用 `app.getLocale()`。
- `startsWith('zh')` → 中文，否则英文。
- 不依赖 renderer i18n；启动失败时 renderer 还没加载。
- 文案放主进程服务，不进 `locales`，避免把启动期依赖拉到 renderer i18n。

### 4.5 正常路径不变

- 数据库正常打开时，初始化顺序、IPC 注册、窗口创建、开发者模式全部不变。
- 不新增 IPC、preload、renderer 代码。
- 不影响 `before-quit` 的 `closeDatabase`。

## 8. 风险与边界

| 风险                | 影响          | 处理                                         |
| ------------------- | ------------- | -------------------------------------------- |
| 启动失败时 app 卡住 | 用户无法退出  | 对话框按钮明确；关闭/取消即退出              |
| 打开目录失败        | 二次异常      | 只记 console，不再弹窗                       |
| 原始错误泄露        | 用户困惑/隐私 | 只显示分类文案；原始错误进 console           |
| 部分初始化残留      | 资源未释放    | catch 里不创建窗口；`before-quit` 关闭数据库 |
| 误伤正常启动        | 回归风险      | 初始化顺序保持不变，只包 try/catch           |
| 无窗口时对话框      | 无父窗口      | 启动阶段直接 `showMessageBox`，不传 window   |
