# 轻叩伴读 TapAlong · 前端组件拆分（桌面版）

**前提：** Electron 项目已搭好，先写前端界面。本文按高保真原型（桌面窗口版）拆组件，不绑定具体框架，但以 React 的“组件 + props + 状态”语义描述，可直接映射到 Vue / Svelte。

---

## 一、拆分原则

1. **屏幕级与组件级分离。** 新页边、伴读是两个屏幕；蒙层、页叠提示是叠加层，不单独成屏。
2. **页边卡是伴读屏幕的固定子组件。** 它不随对谈滚动，编辑态是同一个组件的内部状态，不是新屏幕。
3. **落笔处是伴读屏幕的固定底栏。** 普通落笔、补一句、已合上三种形态由同一组件按 `mode` 切换，不拆成三个组件。
4. **对谈消息按角色拆成三种轻组件。** 老师消息、用户消息、维护动作消息，样式差异大、复用简单。
5. **蒙层是全局叠加层。** 保存中、保存失败、老师没应声共用 Overlay 容器，内部内容不同。
6. **页叠、overlay、composer 模式是状态，不是路由。** 它们由顶层状态机驱动，避免路由碎片化。

---

## 二、屏幕与叠加层划分

| 层级   | 名称              | 说明                                               |
| ------ | ----------------- | -------------------------------------------------- |
| 屏幕   | `NewPageScreen`   | 新页边（含另起一页进入时的返回按钮、页叠过深提示） |
| 屏幕   | `CompanionScreen` | 伴读（页边卡 + 对谈 + 落笔处/已合上提示）          |
| 叠加层 | `OverlayHost`     | 保存中 / 保存失败 / 老师没应声，覆盖整个窗口内容区 |
| 全局   | `AppBar`          | 标题、返回、设置，两个屏幕共用                     |
| 全局   | `ContentColumn`   | 居中内容列（max-width 860px），两个屏幕共用        |

> 设置页暂不在本次拆分范围，`AppBar` 的“设置”按钮先做占位。

## 五、状态归属与数据流

### 5.1 状态分层

| 状态                                               | 归属                                | 说明                                       |
| -------------------------------------------------- | ----------------------------------- | ------------------------------------------ |
| 页叠栈 `stack`、当前索引                           | 顶层状态机                          | 不持久化，关闭即丢                         |
| 当前页 `page`（含 messages、status、title）        | 顶层，来自 IPC 与本地更新           | 主进程是唯一数据源，渲染进程缓存展示       |
| overlay 状态 `saving / failed / teacherNoResponse` | 顶层                                | 由提交动作与调用结果驱动                   |
| composer 模式 `normal / append`                    | `CompanionScreen` 或顶层            | 与当前页绑定                               |
| sayMore 展开                                       | `Composer` 内部或 `CompanionScreen` | 简单布尔                                   |
| editing 与 editDraft                               | `PageCard` 内部或 `CompanionScreen` | 编辑草稿不落库，保存才提交                 |
| 流式临时消息 `streamingText`                       | `CompanionScreen` 或 `TalkStream`   | 收到 `teacher:done` 后合并为正式消息并清空 |
| 新页边草稿                                         | `NewPageScreen` 内部                | 提交成功后清空                             |

> 建议：用轻量 store（Zustand / Pinia）或 `useReducer` 管理顶层状态机；页边卡编辑草稿、sayMore 展开、Composer 输入可用组件本地 state。

### 5.2 关键数据流

**新页边提交：**
AAA text
NewPageForm.onSubmit
→ 校验正文非空
→ 设置 overlay = 'saving'
→ window.tapAlong.savePage({ body, source })
→ 成功：overlay = null，将返回 page 压入 stack，切到 CompanionScreen
→ 失败：overlay = 'failed'，保留草稿
AAA

**伴读发送：**
AAA text
Composer.onSend
→ 本地追加用户消息（乐观更新）
→ 清空输入，typing = true
→ window.tapAlong.askTeacher({ pageId, userText })
→ 订阅 onTeacherChunk：追加/更新临时老师消息
→ onTeacherDone：用最终 reply 替换临时消息，typing = false，按 suggest_close 决定是否展示建议
→ invoke 拒绝：typing = false，overlay = 'teacherNoResponse'
AAA

**题眼更新：**
AAA text
订阅 onTitleUpdated
→ 按 pageId 更新当前页 title
→ PageCardHeader 重渲染
AAA

**合上这页：**
AAA text
MaintenanceMenu.onClose
→ 本地追加老师消息“好，这页先读到这儿。”
→ page.status = 'closed'
→ 约 1s 后弹栈；若栈空回 NewPageScreen，否则回到上一页
→ 同时调用 window.tapAlong.closePage(pageId)
AAA

## 六、与 IPC 的对接点

| 组件 / 动作             | IPC                        | 说明                                                 |
| ----------------------- | -------------------------- | ---------------------------------------------------- |
| `NewPageForm` 提交      | `pages:save`               | 返回 `{ ok, page }`；失败展示 FailedOverlay          |
| `PageCardEditMode` 保存 | `pages:edit`               | 保存后主进程重新取题眼，渲染进程监听 `title:updated` |
| `Composer` 补一句提交   | `pages:append`             | 正文追加，不重新取题眼                               |
| `Composer` 普通落笔     | `teacher:ask`              | 流式；订阅 `teacher:chunk` / `teacher:done`          |
| `MaintenanceMenu` 合上  | `pages:close`              | 状态置 closed，触发弹栈                              |
| 启动 / 进入伴读         | `pages:get` / `pages:list` | 顶层初始化时取当前页                                 |
| 题眼更新                | `title:updated`            | 全局订阅一次，按 pageId 分发                         |

> 建议在 `src/renderer/api/` 下封装一层 `tapAlongApi`，把 `window.tapAlong` 的 raw 调用包成 Promise 与事件订阅，组件不直接碰 `window.tapAlong`。

## 十、建议实现顺序

1. **设计 token 与通用 UI**：`tokens.css`、`Button`、`TextArea`、`InputField`、`StatusBadge`、`Overlay`、`Spinner`。
2. **布局壳**：`AppWindow`、`AppBar`、`ContentColumn`，用静态占位跑通两屏幕切换。
3. **新页边**：`NewPageScreen` + `NewPageForm`，先不接 IPC，本地模拟保存与 overlay。
4. **伴读静态版**：`PageCard`、`TalkStream` 三种消息、`Composer` 静态渲染，用 mock 数据。
5. **接入 IPC**：`pages:save`、`pages:get`、`title:updated`，跑通“收进页边 → 题眼更新”。
6. **流式对接**：`teacher:ask` + `teacher:chunk` + `teacher:done`，实现逐字显示与临时消息替换。
7. **维护动作**：编辑态、补一句模式、维护菜单、合上弹栈。
8. **失败路径**：FailedOverlay、TeacherNoResponseOverlay、页叠过深提示。
