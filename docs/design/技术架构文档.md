# 轻叩伴读 TapAlong · 技术架构文档

**版本：** v0.1（验证阶段）  
**定位：** 桌面端单用户应用，数据全本地，无账号体系，无 Agent 运行时，AI 仅以问句引导用户加深对文字内容的理解。

---

## 一、核心设计约束

本文档的每一个技术决策，都服从以下约束。若后续决策与这些约束冲突，以约束为准。

1. **AI 不干活，只说话。** 模型输出永远是一句问句，或一句建议合上的话。不调用工具、不检索外部数据、不改变系统状态。因此**不引入 Agent 运行时、不引入工具注册表、不做任务规划**。
2. **单轮请求-响应循环。** 用户落笔 → 构造上下文 → 调模型 → 解析 → 展示 → 等待下一次落笔。循环质量取决于 prompt 约束与上下文裁剪，不取决于编排框架。
3. **数据全部在用户本地。** 无账号、无遥测、无云端同步。唯一联网动作是调用 LLM 生成话术，且去向对用户透明（模型服务商可选）。
4. **单用户、单进程、单数据库连接。** 不使用 SQLite 的并发锁概念，改用**单实例锁**从根上消灭多进程冲突。
5. **主进程做所有“重”和“敏感”的事。** 渲染进程只做展示与交互，不持有 API Key、不直接访问文件系统、不发起 LLM 请求。

## 三、进程模型与安全边界

### 3.1 三条铁律

| 进程         | 职责                                                                    | 禁止事项                                              |
| ------------ | ----------------------------------------------------------------------- | ----------------------------------------------------- |
| **渲染进程** | UI 渲染、本地交互状态（输入框内容、菜单展开、滚动位置）、订阅流式 chunk | 不访问文件系统、不持有 API Key、不直接发起网络请求    |
| **Preload**  | 通过 `contextBridge` 暴露窄接口，做类型化 IPC 转发                      | 不包含业务逻辑、不暴露完整 `ipcRenderer` 或 Node 能力 |
| **主进程**   | 持有 SQLite 连接、API Key、LLM 调用循环、题眼提取、所有持久化           | —                                                     |

### 3.2 BrowserWindow 安全配置

```typescript
new BrowserWindow({
  webPreferences: {
    contextIsolation: true,
    nodeIntegration: false,
    sandbox: false, // preload 需要 require electron
    preload: path.join(__dirname, 'preload.js'),
  },
});
```

`sandbox: false` 是 preload 使用 `contextBridge` 的前提；preload 本身保持最小，不引入业务逻辑。

### 3.3 Preload 接口设计（克制原则）

```typescript
// src/preload/index.ts
import { contextBridge, ipcRenderer } from 'electron';

contextBridge.exposeInMainWorld('tapAlong', {
  // 数据读取
  listPages: () => ipcRenderer.invoke('pages:list'),
  getPage: (id: number) => ipcRenderer.invoke('pages:get', id),

  // 新页边
  savePage: (payload: { body: string; source: string }) =>
    ipcRenderer.invoke('pages:save', payload),

  // 伴读
  askTeacher: (payload: { pageId: number; userText: string }) =>
    ipcRenderer.invoke('teacher:ask', payload),
  onTeacherChunk: (cb: (chunk: string) => void) => {
    const listener = (_e, chunk: string) => cb(chunk);
    ipcRenderer.on('teacher:chunk', listener);
    return () => ipcRenderer.removeListener('teacher:chunk', listener);
  },
  onTeacherDone: (cb: (result: TeacherResult) => void) => {
    const listener = (_e, result: TeacherResult) => cb(result);
    ipcRenderer.on('teacher:done', listener);
    return () => ipcRenderer.removeListener('teacher:done', listener);
  },

  // 维护动作
  editNote: (payload: { pageId: number; body: string }) =>
    ipcRenderer.invoke('pages:edit', payload),
  appendNote: (payload: { pageId: number; text: string }) =>
    ipcRenderer.invoke('pages:append', payload),
  closePage: (pageId: number) => ipcRenderer.invoke('pages:close', pageId),

  // 题眼更新订阅
  onTitleUpdated: (
    cb: (payload: { pageId: number; title: string }) => void,
  ) => {
    const listener = (_e, payload) => cb(payload);
    ipcRenderer.on('title:updated', listener);
    return () => ipcRenderer.removeListener('title:updated', listener);
  },
});
```

**原则：** 每个方法都对应一个明确的用户动作或数据需求。不暴露 `invoke(channel, ...args)` 这种万能接口。

## 四、技术栈选型

| 层         | 选型                                                  | 理由                                              |
| ---------- | ----------------------------------------------------- | ------------------------------------------------- |
| 桌面壳     | Electron                                              | 与 `deepseek-harness/apps/desktop` 一致，生态成熟 |
| 主进程语言 | TypeScript                                            | 类型安全，Repository 层可直接复用类型             |
| 数据库     | `node:sqlite`（`DatabaseSync`）                       | 内置模块，避开原生模块 ABI 编译与打包路径问题     |
| 配置存储   | `electron-store`                                      | 轻量 JSON，原子写入                               |
| 密钥存储   | `safeStorage`（**异步 API**）                         | OS 密钥链，主进程专用                             |
| LLM 调用   | 主进程直调 DeepSeek API（`stream: true`）             | 不需要 Agent 运行时，单轮循环足够                 |
| 流式推送   | `ipcMain.handle` 启动 + `webContents.send` 推送 chunk | 标准 Electron 流式模式                            |
| 前端       | 验证阶段可直接嵌入现有 HTML；正式阶段 React / Vue     | 验证优先，框架化延后                              |
| 构建       | Vite（需外部化 `node:sqlite`）                        | 见 §6.1                                           |

**不引入：** Agent 运行时、工具注册表、ORM（Drizzle 等）、连接池、多进程模型、服务端。

## 五、数据层

### 5.1 数据库连接

```typescript
// src/main/db/client.ts
import { DatabaseSync } from 'node:sqlite';
import { join } from 'node:path';
import { app } from 'electron';

const dbPath = join(app.getPath('userData'), 'tap-along.db');
export const db = new DatabaseSync(dbPath);

db.exec('PRAGMA journal_mode = WAL');
db.exec('PRAGMA foreign_keys = ON');
```

**关于锁的决策：**

- **不设置 `busy_timeout`**。单进程单连接场景下不会触发 `SQLITE_BUSY`。
- **不使用连接池**。一个 `DatabaseSync` 实例贯穿主进程生命周期。
- **多进程冲突由单实例锁消灭**（见 §11）。

### 5.2 建表

```sql
CREATE TABLE IF NOT EXISTS pages (
    id                   INTEGER PRIMARY KEY AUTOINCREMENT,
    edge_title           TEXT,
    body                 TEXT NOT NULL,
    source               TEXT,
    parse_status         TEXT NOT NULL DEFAULT 'pending',
    companion_log        TEXT,           -- JSON 数组，对谈记录
    page_status          TEXT NOT NULL DEFAULT 'reading',
    teaching_round_count INTEGER DEFAULT 0,
    created_at           TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at           TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_pages_status ON pages(page_status);
CREATE INDEX IF NOT EXISTS idx_pages_updated ON pages(updated_at DESC);
```

验证阶段直接 `CREATE TABLE IF NOT EXISTS`，不做迁移框架。schema 变更时手动处理。

### 5.3 Repository 层

```typescript
// src/main/db/pages.ts
import { DatabaseSync } from 'node:sqlite';

export interface PageRow {
  id: number;
  edge_title: string | null;
  body: string;
  source: string | null;
  parse_status: 'pending' | 'reading' | 'done' | 'failed';
  companion_log: string | null;
  page_status: 'reading' | 'closed';
  teaching_round_count: number;
  created_at: string;
  updated_at: string;
}

export class PagesRepository {
  constructor(private db: DatabaseSync) {}

  private readonly insertStmt = this.db.prepare(`
    INSERT INTO pages (body, source, parse_status, page_status)
    VALUES (?, ?, 'pending', 'reading')
  `);

  private readonly getStmt = this.db.prepare(
    `SELECT * FROM pages WHERE id = ?`,
  );

  private readonly updateBodyStmt = this.db.prepare(`
    UPDATE pages SET body = ?, edge_title = ?, updated_at = CURRENT_TIMESTAMP WHERE id = ?
  `);

  private readonly updateTitleStmt = this.db.prepare(`
    UPDATE pages SET edge_title = ?, parse_status = 'done', updated_at = CURRENT_TIMESTAMP WHERE id = ?
  `);

  private readonly updateLogStmt = this.db.prepare(`
    UPDATE pages SET companion_log = ?, teaching_round_count = ?, updated_at = CURRENT_TIMESTAMP WHERE id = ?
  `);

  private readonly closeStmt = this.db.prepare(`
    UPDATE pages SET page_status = 'closed', updated_at = CURRENT_TIMESTAMP WHERE id = ?
  `);

  create(body: string, source: string): number {
    const r = this.insertStmt.run(body, source || null);
    return Number(r.lastInsertRowid);
  }

  findById(id: number): PageRow | undefined {
    return this.getStmt.get(id) as PageRow | undefined;
  }

  updateBodyAndTitle(id: number, body: string, title: string | null) {
    this.updateBodyStmt.run(body, title, id);
  }

  updateTitle(id: number, title: string) {
    this.updateTitleStmt.run(title, id);
  }

  updateLog(id: number, log: unknown[], roundCount: number) {
    this.updateLogStmt.run(JSON.stringify(log), roundCount, id);
  }

  close(id: number) {
    this.closeStmt.run(id);
  }

  withTransaction<T>(fn: () => T): T {
    this.db.exec('BEGIN');
    try {
      const result = fn();
      this.db.exec('COMMIT');
      return result;
    } catch (e) {
      this.db.exec('ROLLBACK');
      throw e;
    }
  }
}
```

**事务的使用场景：** 改批注（更新正文 + 重置题眼 + 更新日志）、补一句（追加正文 + 更新日志）等涉及多步写入的操作，必须包在 `withTransaction` 内，保证原子性。这与并发无关，是正确性问题。

**事务的写法约束：** 事务块内**不得跨 `await`**。`DatabaseSync` 是同步 API，事务内所有操作同步完成。LLM 调用在事务外完成，拿到结果后再进入事务写入。

### 5.4 WAL 维护

```typescript
// src/main/index.ts
app.on('before-quit', () => {
  try {
    db.exec('PRAGMA wal_checkpoint(TRUNCATE)');
    db.close();
  } catch {
    /* 已关闭则忽略 */
  }
});
```

这不是并发控制，是**文件维护**：防止 `-wal` 文件长期增长，并保证退出时主库文件状态一致。

## 六、LLM 服务层

### 6.1 上下文构造

```typescript
// src/main/services/teacher.ts
function buildMessages(page: PageRow, recentRounds = 6): ChatMessage[] {
  const log: LogEntry[] = page.companion_log
    ? JSON.parse(page.companion_log)
    : [];
  const recent = log.slice(-recentRounds * 2); // 一轮含老师+用户

  return [
    { role: 'system', content: SYSTEM_PROMPT },
    {
      role: 'user',
      content: [
        `笔记正文：${page.body}`,
        `出处：${page.source ?? '未标注'}`,
        `当前轮次：第 ${page.teaching_round_count + 1} 轮`,
        `最近对谈：\n${recent.map((m) => `${m.role === 'teacher' ? '老师' : '你'}：${m.text}`).join('\n') || '（尚无）'}`,
        `请给出你的回应。`,
      ].join('\n\n'),
    },
  ];
}
```

**历史裁剪在渲染进程之外完成。** 渲染进程只负责展示 `companion_log` 的全部内容（“前面聊过的”折叠），但不参与“拼进 prompt 的历史取哪几轮”的决策。

### 6.2 System Prompt 约束

```text
你是伴读老师。你的唯一任务是：针对用户刚写下的内容或刚说的话，提出一个问题，
引导他自己把理解往前推一步。

硬性约束：
1. 只输出问句，不解释、不建议、不总结、不评价。
2. 问题必须指向用户文字中具体的词或判断，给出两个互斥选项，或要求用户推翻。
3. 如果觉得这轮已经聊透，没有值得追问的，输出建议合上的信号。
4. 宁可沉默，不可硬凑。不要为了追问而追问。

输出格式（严格 JSON）：
{ "reply": "你的问句或建议合上的话", "suggest_close": true | false }
```

**输出解析必须容错：** 模型可能不返回严格 JSON。解析策略是“先尝试 `JSON.parse`，失败则把整个文本作为 `reply`，`suggest_close` 置 `false`”。不要因为解析失败而让用户看到空白。

### 6.3 流式调用与推送

```typescript
export async function askTeacher(
  pageId: number,
  userText: string,
  send: (chunk: string) => void,
): Promise<TeacherResult> {
  const page = repo.findById(pageId);
  if (!page) throw new Error('page not found');

  // 1. 先把用户消息写入日志
  const log = page.companion_log ? JSON.parse(page.companion_log) : [];
  log.push({ role: 'user', text: userText, ts: Date.now() });
  repo.updateLog(pageId, log, page.teaching_round_count);

  // 2. 调模型（流式）
  const messages = buildMessages({
    ...page,
    companion_log: JSON.stringify(log),
  });
  let raw = '';
  let buffer = '';
  const stream = await llm.chat.completions.create({
    model: 'deepseek-chat',
    messages,
    stream: true,
    response_format: { type: 'json_object' },
  });

  for await (const part of stream) {
    const delta = part.choices[0]?.delta?.content ?? '';
    raw += delta;
    buffer += delta;
    // 微批：每 3 个 token 或 50ms 推送一次
    if (buffer.length >= 3) {
      send(buffer);
      buffer = '';
    }
  }
  if (buffer) send(buffer);

  // 3. 解析
  const result = parseTeacherOutput(raw);

  // 4. 写回日志
  log.push({ role: 'teacher', text: result.reply, ts: Date.now() });
  repo.updateLog(pageId, log, page.teaching_round_count + 1);

  return result;
}
```

**渲染进程侧：** 收到 chunk 就追加到当前对谈末尾（UI 层的临时消息），收到 `done` 后用最终 `reply` 覆盖临时消息，并记录 `suggest_close` 状态。

### 6.4 题眼异步提取

题眼提取与伴读循环**完全解耦**，在“收进页边”成功后立即发起，不阻塞老师开口。

```typescript
export async function extractTitle(
  pageId: number,
  body: string,
): Promise<void> {
  try {
    const title = await llm.chat.completions.create({
      model: 'deepseek-chat',
      messages: [
        {
          role: 'system',
          content: '提取这段笔记的短标题，不超过 12 个字，只输出标题本身。',
        },
        { role: 'user', content: body },
      ],
      max_tokens: 20,
    });
    repo.updateTitle(pageId, title.trim());
    win.webContents.send('title:updated', { pageId, title: title.trim() });
  } catch {
    // 回退：正文首行截取
    const fallback = body.split('\n')[0].trim().slice(0, 12) || '未命名';
    repo.updateTitle(pageId, fallback);
    win.webContents.send('title:updated', { pageId, title: fallback });
  }
}
```

## 七、IPC 契约

### 7.1 通道清单

| 通道            | 方向            | 类型   | 说明                |
| --------------- | --------------- | ------ | ------------------- |
| `pages:list`    | renderer → main | invoke | 列出最近页          |
| `pages:get`     | renderer → main | invoke | 取单页详情          |
| `pages:save`    | renderer → main | invoke | 新页边收进          |
| `pages:edit`    | renderer → main | invoke | 改批注              |
| `pages:append`  | renderer → main | invoke | 补一句              |
| `pages:close`   | renderer → main | invoke | 合上这页            |
| `teacher:ask`   | renderer → main | invoke | 发起一次老师回应    |
| `teacher:chunk` | main → renderer | send   | 流式 chunk          |
| `teacher:done`  | main → renderer | send   | 流结束 + 结构化结果 |
| `title:updated` | main → renderer | send   | 题眼更新            |

### 7.2 错误处理

所有 `invoke` 处理器用统一的错误包装：

```typescript
ipcMain.handle('pages:save', async (_e, { body, source }) => {
  try {
    const id = repo.create(body, source);
    const page = repo.findById(id);
    // 异步题眼，不阻塞返回
    extractTitle(id, body);
    return { ok: true, page };
  } catch (err) {
    return { ok: false, error: '这一句没送进去。' };
  }
});
```

渲染进程根据 `ok` 字段决定展示正常流程还是失败态（回到页边 / 再试一次）。**失败时不弹模态框，不丢内容。**

老师调用的失败处理：

- `teacher:ask` 抛出异常 → 渲染进程收到 invoke 拒绝 → 展示“老师暂时没应声，要再试一次吗？”并提供重试按钮。
- 重试时保留用户原文，重新发起同一个 `teacher:ask`（用户消息已在第一次调用时写入日志，重试时**不重复写入**，需在服务层用 `requestId` 去重或在重试时标记）。

## 八、状态机与页叠

### 8.1 页面状态

```text
pending（刚创建，等待题眼） → reading（在读） → closed（已合上）
                 ↓ 失败
              failed（没送进去，可重试）
```

`parse_status` 与 `page_status` 分开维护：前者描述题眼/嵌入处理状态，后者描述伴读生命周期。文档中的“状态：● 在读 / ✓ 已合上”由 `page_status` 驱动。

### 8.2 页叠（临时，不持久化）

页叠存在于**渲染进程内存**或主进程的会话状态中，不写入数据库。规则：

- “另起一页”压栈；当前页保持 `reading`，日志保留。
- “翻回去”弹栈，不触发老师。
- “合上这页”将当前页置 `closed`，自动弹栈；若上一页仍 `reading`，老师继续；若已 `closed`，不自动开口。
- 页叠深度上限 3–5 层，超过时提示“页叠得有点深了，先合上一页再继续？”。
- 应用关闭后页叠丢失，下次打开回到最近一页 `reading` 的页。

```text
      llm.ts                 # DeepSeek API 客户端封装（可替换）
      secrets.ts             # safeStorage 封装（API Key 读写）
    ipc/
      handlers.ts            # 所有 ipcMain.handle / on 注册
  preload/
    index.ts                 # contextBridge 窄接口
  renderer/
    ...                      # UI（验证阶段可为静态 HTML）
```

**依赖方向：** `services` → `db`（通过 Repository 注入），`ipc` → `services`，`renderer` → `preload` → `ipc`。`db` 不依赖 `services`，`services` 不依赖 `ipc`。

## 十、启动与退出流程

### 10.1 启动

```text
app.whenReady()
  → requestSingleInstanceLock() 失败则 quit
  → 初始化 DatabaseSync + WAL
  → 执行 CREATE TABLE IF NOT EXISTS
  → 构建 PagesRepository
  → 注册 IPC handlers
  → 创建 BrowserWindow（加载渲染进程）
  → 查询最近一页 reading 的页；有则渲染进程跳转伴读，无则新页边
```

### 10.2 退出

```text
app.on('before-quit')
  → PRAGMA wal_checkpoint(TRUNCATE)
  → db.close()
```

### 10.3 单实例锁

```typescript
const gotLock = app.requestSingleInstanceLock();
if (!gotLock) {
  app.quit();
} else {
  app.on('second-instance', () => {
    const win = BrowserWindow.getAllWindows()[0];
    if (win) {
      if (win.isMinimized()) win.restore();
      win.focus();
    }
  });
}
```

这是**从根上消灭多进程写冲突**的唯一手段，比任何 SQLite 锁配置都干净。

## 十二、验证阶段的最小可行路径

按依赖顺序，建议的验证步骤：

1. **单实例锁 + DatabaseSync + CREATE TABLE**：应用能启动、能退出、db 文件生成在 `userData` 下。
2. **`pages:save` + `pages:get`**：新页边能收进、能读回，题眼异步更新（先用 mock 标题验证链路）。
3. **`teacher:ask` + `teacher:chunk` + `teacher:done`**：接真实 DeepSeek API，流式 chunk 能到渲染进程并逐字显示。
4. **维护动作**：`pages:edit` / `pages:append` / `pages:close` 走通，事务边界正确。
5. **失败路径**：API Key 无效时展示“老师暂时没应声”；保存失败时展示“这一句没送进去”。
6. **页叠**：纯渲染进程状态，验证压栈/弹栈/合上后的自动翻回。

每一步都可独立验证，且不依赖后续步骤。第 1、2 步不需要 API Key 即可完成。
